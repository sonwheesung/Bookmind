# Reload Docs — 컴팩트 후 문서 전체 재적재 (범용)

`/compact`는 대화를 요약하며 **문서의 세부(수치·계약·구현 위치)를 잃는다**. 프로젝트의 `docs/`(또는 그에 준하는 문서 디렉토리)가 단일 진실 원천이면, 요약 직후·새 세션 작업 전에 **문서 전체를 한 번에 다시 읽어** 맥락을 복원한다.

## 무엇을 읽나

1. 루트 에이전트 지침 — `AGENTS.md` / `CLAUDE.md`(있으면).
2. 문서 디렉토리 전체 — 보통 `docs/**/*.md`. 다른 이름이면(`documentation/`·`wiki/`·`spec/`) 그쪽. 인덱스(README/00) 먼저로 지도를 잡고 나머지.
3. 하위 디렉토리(캐릭터·서브시스템 등)도 빠짐없이.

## ★ 공용 문서(`C:\project\common`)도 함께 재적재 (프로젝트 불문 항상)

프로젝트 문서만이 아니라 **여러 프로젝트가 공유하는 기준 문서**가 `C:\project\common`에 있다.
재적재 시 그 폴더의 **문서를 전부 다시 읽는다** — 프로젝트 `docs/`와 **함께**. 이 문서들은 한 프로젝트
세션이 잊기 쉬운 **크로스-프로젝트 사실**(사업자·법적 상호·스토어 등록 필드·계정 상태·출시/릴리스 절차
등)을 담아, 세션이 낡은 값이나 기억으로 판단하는 걸 막는다. (예: `BUSINESS_INFO.md` = 사업자·서비스
정보 단일 출처 · `PLAY_RELEASE_AUTOMATION.md` = Play 출시 자동화 절차 · `ASSET_GENERATION.md` = ChatGPT 이미지
생성·크로마키·픽셀화 파이프라인과 함정 도감.)

- **대상 = `C:\project\common` 아래 모든 콘텐츠 `.md`** (루트 + 콘텐츠 하위 폴더). 새 문서가 추가돼도
  글롭이 자동으로 잡는다 — **하나도 빠뜨리지 말 것**(사용자 지시: "여기 문서 전부 다").
- `.claude/`(스킬 `SKILL.md`·에이전트 정의)는 **지식 문서가 아니라 도구 정의**라 지식 재적재 대상이
  아니다 — 스킬은 호출될 때 로드되고 에이전트는 스폰될 때 로드된다. 콘텐츠 문서만 읽는다.

## 실행

```
ls AGENTS.md CLAUDE.md 2>/dev/null
ls docs/**/*.md                              # 프로젝트 문서(또는 Glob "docs/**/*.md" / 실제 문서 디렉토리)
ls C:/project/common/*.md                    # ★공용 기준 문서 전부(BUSINESS_INFO·PLAY_RELEASE_AUTOMATION 등)
#   콘텐츠 하위 폴더가 있으면: Glob "C:/project/common/**/*.md" 에서 .claude/** 제외분
```

반환된 전 파일(**프로젝트 docs + 공용 common 문서**)을 5~6개씩 묶어 Read 도구로 **병렬 배치**(한
메시지에 여러 Read). 목록과 대조해 누락 없이. 큰 파일은 잘리면 페이지 넘겨 끝까지.

## 읽고 난 뒤

- 장황한 요약 금지 — "문서 N개 재적재 완료" + 직전 작업 맥락 한 줄.
- 곧바로 직전 task 복귀. 재적재한 내용을 근거로 판단(다시 Read 불필요).
- 문서가 코드와 어긋나면 코드 확인 — 문서는 작성 시점 스냅샷.

## ⚠ 컴팩트로 자주 잊는 규율 — 버그 찾으면 "현재 원인 + 이전이 왜 못 잡았나"를 함께 문서화

컴팩트 후 가장 자주 빠뜨리는 작업이다. **이번 세션에서 버그/오류를 찾거나 고쳤다면**, 고치고 끝내지 말고 프로젝트의 엣지케이스/회귀 레지스트리 문서(있으면 그 파일, 없으면 적절한 docs 위치)에 다음을 **함께** 남긴다:

1. **현재 발견** — 증상 / 원인 / 수정 / 재검증.
2. **사각 분석** — **"왜 기존 테스트·검증이 이걸 못 잡았나"**. 테스트 PASS인데 실제 버그였다면 그건 거짓 확신이다.
3. **사각 닫기** — 그 구멍을 메우는 테스트/케이스를 추가해야 수정이 **완료**. (가능하면 메타 가드로 기계 강제.)

> "고침"만으로 끝내지 말 것 — 현재 원인과 과거 사각을 한 쌍으로 남겨 같은 종류 버그가 다시 새지 않게 한다. 프로젝트에 규약 문서가 있으면 그 형식을 따른다.

## ⚠ 개발 진행 시 — 문서 먼저, 코드 나중 (docs-first, 예외 없음)

기능·시스템·수치·콘텐츠를 새로 만들거나 바꿀 때는 **무조건 문서를 먼저 작성·갱신한 뒤에 코딩**한다. 순서를 뒤집지 않는다.

- **이유: 코드는 틀려도 되지만 문서는 틀리면 안 된다.** docs가 단일 진실 원천이다. 코드는 버그가 나면 고치면 되지만, 문서가 틀리면 모든 후속 판단(다른 세션·재구현·테스트 기준)의 근거가 오염된다. 설계를 먼저 문서에 못 박아 정합성을 확정하고, 코드는 그 문서를 구현·검증하는 것으로 둔다.
- **흐름**: ① 해당 문서(설계·계약·수치)에 무엇을 만들지 먼저 적는다 → ② 그 문서를 기준으로 코드 작성 → ③ 영향 계층 테스트로 코드가 문서대로인지 검증. 어긋나면 코드를 문서에 맞춘다(설계를 바꿀 거면 문서를 먼저 고친 뒤 코드).
- 작은 수정도 예외 없음 — 수치 한 줄을 바꿔도 문서의 그 수치/기준을 먼저 갱신하고 코드를 따라오게 한다.

## ⚠ 추측·추정 금지 조약 (재확인)

코드·문서·수치를 **직접 확인한 사실에만** 근거해 답하고 작업한다.

- 파일 내용·함수 시그니처·수치·계약을 기억이나 인상으로 단정하지 말 것 — Read/Grep으로 **실물을 본 뒤** 말한다. 큰 파일은 잘린 중간에서 단정 금지(끝까지 읽기).
- "아마 이럴 것이다"식 추정으로 코드를 짜거나 사용자에게 보고하지 않는다. 모르면 확인하고, 확인 불가면 "확인 불가"라고 명시한다.
- 모호한 규칙은 추측해 얼버무리지 말고 명확한 규칙으로 확정해 제시 → 사용자 합의 후 문서화.

## 트리거

`/compact` 직후 1순위. "문서 다시 읽어줘", "reload docs", "컴팩트했어" 류도 트리거. 한 주제만 필요하면 전체 대신 해당 문서만 Read.
