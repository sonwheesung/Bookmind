# BACKUP_SYSTEM — 로컬 내보내기 · 가져오기 (결정 #15)

> 기기 안의 지식 전부를 **파일 하나로** 꺼내고(내보내기) 되돌리는(가져오기) 기능.
> 서버·클라우드·계정을 쓰지 않는다 — 파일은 OS 공유 시트로 사용자가 고른 곳에 놓이고 **앱은 그 뒤를 모른다.**
>
> 결정 배경은 [`../CLAUDE.md`](../CLAUDE.md) §14 #15, 스키마 정본은 [`DATABASE.md`](./DATABASE.md),
> 착수 순서는 [`PLAN.md`](./PLAN.md) Phase 2.
> 작성 2026-09-09 — **문서 선행**(코드 착수 전). 여기 적힌 것과 코드가 다르면 코드를 고친다.

## 0. 왜 v1.0 에 있나 — 이것만이 무료 사용자의 전손을 닫는다

결정 #1(지식의 정본은 기기다)의 대가는 **기기 교체 시 전손**이다.
그 대가를 닫는 장치가 둘인데 하나만으로는 안 닫힌다:

| 장치 | 언제 | 누구에게 |
|---|---|---|
| 암호화 백업 금고(#6) | v1.1 | **Premium 만** |
| 🔴 **로컬 내보내기/가져오기(#15)** | **v1.0** | **전원(무료 포함)** |

🔴 **금고만 있으면 무료 사용자의 전손이 영원히 안 닫힌다.** 형제 Idea Repository 가 같은 자리에서
낸 결론을 승계한다 — *"자기 데이터를 꺼내는 데 돈을 받는 것"* 이 기둥과 정면충돌한다.

🟢 **유료 가치가 안 깎인다.** 유료는 *자동 · 암호화 · 클라우드 금고*이고 무료는 *수동 파일 한 장*이다.
사용자가 직접 누르고, 직접 어딘가에 두고, 직접 잃어버릴 수 있다 — 그게 무료판이다.

## 1. 결정

| 결정 | 내용 · 근거 |
|---|---|
| **무료 · v1.0** | 결정 #15. Premium 게이트를 세우지 않는다 |
| 서버 업로드 🚫 · 자동 동기화 🚫 | 기둥 2. 파일은 사용자 손에만 간다 |
| 형식 = **JSON 한 파일, 평문** | 단순하고 검증 가능하고 다른 도구로도 읽힌다. 🔴 **암호화 없음** — 비밀번호 분실 = 영구 손실이라 v1 에 넣지 않는다. 대신 화면에 고지한다(§6) |
| 내보내기 = **OS 공유 시트** | `expo-sharing`. 저장 위치·권한·SAF 를 전부 OS 에 맡긴다 |
| 가져오기 = **파일 선택 → 미리보기 → 병합 / 교체** | `expo-document-picker`. 교체는 파괴적이라 2단계 확인. 전부 **한 트랜잭션** — 중간에 실패하면 아무것도 안 바뀐다 |
| 범위 = **사용자 데이터 11표**(`meta` 제외) | §2. `meta` 는 앱 내부 상태(스키마 버전)이지 사용자 데이터가 아니다(`DATABASE.md` §1.1 예외) |
| 🔴 **tombstone 도 함께 내보낸다** | `deleted_at` 이 있는 행을 빼면, 파일을 가져올 때 **지운 것이 되살아난다.** 결정 #8 이 tombstone 을 둔 이유가 정확히 이 병합이다 |
| 자동 백업 · 백업 알림 🚫 | 알림 예산은 복습(기둥 7)에 전부 쓴다. 화면에 **마지막 내보내기 날짜**만 보여 스스로 챙기게 한다 |

## 2. 파일 형식 (formatVersion 1)

```jsonc
{
  "format": "reread-backup",        // 고정 식별자 — 다른 JSON 을 잘못 고르면 여기서 거른다
  "formatVersion": 1,               // 파일 구조 버전. 읽는 쪽이 모르는 값이면 거부
  "schemaVersion": 4,               // 🔴 meta.schema_version 이다 (PRAGMA user_version 이 아니다 — DATABASE §1.3)
  "app": { "version": "1.0.0", "platform": "android" },
  "exportedAt": "2026-09-09T05:12:00.000Z",
  "counts": { "books": 3, "knowledge": 42, "thoughts": 18, "practices": 5 },
  "data": {
    "books":            [ /* books 행 그대로 (snake_case, 전 컬럼) */ ],
    "knowledge":        [ ],
    "thoughts":         [ ],
    "ai_analyses":      [ ],
    "recall_questions": [ ],
    "review_schedules": [ ],
    "review_logs":      [ ],
    "practices":        [ ],
    "practice_logs":    [ ],
    "tags":             [ ],
    "knowledge_tags":   [ ]
  }
}
```

- 행은 **DB 행 그대로**(snake_case) — `SELECT *` 를 그대로 직렬화한다. 매핑 계층이 없어 컬럼이 새면
  누락되지 않고, `DATABASE.md` §2 가 곧 파일 명세가 된다.
- 표 순서는 `db/schema.ts` 의 `TABLE_NAMES` 에서 `meta` 를 뺀 것과 **같아야 한다**(가드가 잰다 — §7).
- 파일명 `ReRead-backup-YYYYMMDD-HHmm.json`(기기 로컬 시각) · MIME `application/json`.
- `counts` 는 **미리보기용**이지 검증용이 아니다. 틀려도 거부하지 않는다 — 실제 적용은 `data` 로 한다.
- `formatVersion` 은 **구조가 바뀔 때만** 올린다. 마이그레이션으로 컬럼이 하나 늘었다고 올리지 않는다 —
  가져오기가 **아는 컬럼만 골라 넣고 모르는 컬럼은 버리므로**(§4.3) 구/신 앱이 서로 읽을 수 있다.
- 크기 상한 **20MB**(문자열 기준). 그 위는 거부한다 — 문장 앱이라 실사용은 수 MB 안쪽이다.

## 3. 내보내기

```
설정 → 백업 → [파일로 내보내기]
 → 11표 SELECT *(tombstone 포함, 한 읽기 트랜잭션) → JSON.stringify
 → 캐시에 파일 쓰기(expo-file-system)
 → Sharing.shareAsync(uri, { mimeType: 'application/json' })
 → 시트가 닫히면 임시 파일 삭제 → lastExportedAt 저장
```

- 🔴 **`selectAll` 을 쓰지 않는다.** 그 헬퍼는 `deleted_at IS NULL` 을 붙인다(`db/sql.ts`) — 내보내기는
  `includeDeleted` 경로로 간다. 이걸 틀리면 파일이 조용히 tombstone 을 빠뜨린다.
- 공유 시트 **취소도 성공으로 치지 않는다** — 다만 OS 가 성공/취소를 구분해 주지 않으므로
  `lastExportedAt` 의 뜻은 *"시트를 열었다"* 이고, 화면 문구도 **"마지막 내보내기"** 까지만 쓴다.
  🚫 *"백업됨"* 이라고 쓰지 않는다(거짓이 될 수 있다).
- 공유 불가 기기(`Sharing.isAvailableAsync()` false)는 버튼을 비활성화하고 사유를 보여준다.
- **데이터가 0건이어도 내보내기를 막지 않는다** — 빈 파일도 유효한 파일이다.

## 4. 가져오기

### 4.1 흐름

```
[파일에서 가져오기] → DocumentPicker(application/json) → 읽기 → 검증(§4.2)
 → 미리보기: "책 3 · 문장 42 · 생각 18 · 실천 5 (2026년 9월 9일 내보냄)"
 → [합치기] [바꾸기] [취소]
 → 바꾸기면 2차 확인("이 기기의 내용이 파일 내용으로 바뀝니다. 되돌릴 수 없습니다.")
 → 한 트랜잭션 적용 → 결과("추가 N · 갱신 N · 건너뜀 N")
```

### 4.2 검증 — 하나라도 틀리면 **거부**

| 검사 | 실패 키 |
|---|---|
| 크기 ≤ 20MB · JSON 파싱 성공 | `backup.import.invalidFile` |
| `format === 'reread-backup'` | `backup.import.invalidFile` |
| `formatVersion` ≤ 앱이 아는 최대(1) | `backup.import.newerApp` |
| 🔴 `schemaVersion` ≤ 앱의 `CODE_SCHEMA_VERSION` | `backup.import.newerApp` |
| `data` 의 11배열 존재 · 각 행의 PK 가 문자열 | `backup.import.invalidFile` |

- 🔴 **신버전 파일을 구버전 앱에서 열지 않는다.** 우리는 expand-only(§1.3)라 컬럼이 늘기만 하는데,
  구버전 앱은 새 컬럼을 **버리고** 저장한다 — 조용한 데이터 손실이고 되돌릴 수 없다.
  그래서 `newerApp` 은 경고가 아니라 **거부**다.
- CHECK·FK·UNIQUE 위반은 **DB 에 맡긴다** — 걸리면 트랜잭션이 통째로 롤백되고 `backup.import.failed`.

### 4.3 합치기(Merge) — 기본

PK 가 UUID 라 서로 다른 기기의 행이 우연히 충돌하지 않는다는 전제(결정 #8 이 이걸 위해 있다).

| 표 | 같은 PK 가 있을 때 | 없을 때 |
|---|---|---|
| `books` · `knowledge` · `thoughts` · `ai_analyses` · `recall_questions` · `practices` · `practice_logs` | **`updated_at` 이 파일 쪽이 크면 덮어쓴다**(전 컬럼, `deleted_at` 포함), 아니면 로컬 유지 | 삽입 |
| `review_schedules` (PK = `knowledge_id`) | 같은 규칙(`updated_at` 비교) | 지식이 있을 때만 삽입 |
| 🔴 `review_logs` | **건너뛴다**(같은 id 는 같은 사건이다) | 삽입 |
| `tags` | 로컬 유지 | 같은 `name` 이 있으면 **파일 id → 로컬 id 로 재매핑**, 없으면 삽입 |
| `knowledge_tags` (PK = 두 컬럼) | `updated_at` 비교 | 재매핑을 적용해 삽입 |

- 🔴 **`deleted_at` 도 값이다.** 파일 쪽 `updated_at` 이 크면 로컬의 살아 있는 행이 **tombstone 으로
  덮인다** — 그게 맞다. "저쪽에서 나중에 지웠다"를 이쪽이 무시하면 지운 것이 되살아난다.
- 🔴 **`tags.name` 재매핑은 §1.4 되살리기 규칙을 먼저 본다.** 같은 이름의 tombstone 이 로컬에 있으면
  삽입하면 UNIQUE 로 터진다 — 되살려서 그 id 로 재매핑한다.
- 컬럼 처리: 파일 행에서 **앱이 아는 컬럼만** 골라 넣는다. 모르는 컬럼은 버리고, 빠진 컬럼은 DB DEFAULT.
- `updated_at` 은 **파일 값을 보존한다.** 가져오기는 사용자의 편집이 아니다 — 여기서 `now()` 를 찍으면
  다음 가져오기 때 이 기기가 항상 이긴다.
- 끝에 고아 태그를 정리한다(`db/cascade.ts` 의 `NOT EXISTS` 와 같은 방식).

### 4.4 바꾸기(Replace)

한 트랜잭션에서 **자식 → 부모 순으로 전부 DELETE**
(`knowledge_tags → practice_logs → review_logs → review_schedules → recall_questions → ai_analyses →
thoughts → practices → knowledge → tags → books`) 한 뒤,
**부모 → 자식 순으로** 파일 내용을 넣는다. `meta` 는 건드리지 않는다.

🔴 물리 삭제다(tombstone 이 아니다). 기기를 파일 상태로 되돌리는 것이지 "지웠다"고 기록하는 게 아니다.

## 5. 화면 `/backup` (설정 → 백업)

```
백업

문장과 생각은 이 기기에만 있습니다.
파일로 내보내 두면 기기를 바꿔도 되돌릴 수 있습니다.

[ 파일로 내보내기 ]
  마지막 내보내기: 2026년 9월 9일        ← 없으면 "아직 없습니다"

[ 파일에서 가져오기 ]

내보낸 파일에는 저장한 내용이 그대로(암호화 없이) 들어 있습니다.
안전한 곳에 보관하세요. 파일은 서버로 보내지지 않습니다.
```

- 🔴 문구는 `DESIGN_REVIEW.md` 창구를 거친다 — *"첫 백업을 만들어보세요!"* 같은 유도 문구는 안 쓴다.
- 정직 규칙: 🚫 *"백업하면 안전합니다"* 라고 쓰지 않는다. 파일 분실·유출은 사용자 영역이다.

## 6. 고지 · 법무

- 파일은 **앱이 만들고 OS 공유 시트가 전달한다.** 회사는 파일을 받지도 보지도 않는다 →
  Play 데이터 보안 선언에 수집·공유 항목이 늘지 않는다.
- 평문이므로 화면과 처리방침 양쪽에 *"내보낸 파일에는 내용이 그대로 들어 있다"* 를 적는다.
- 탈퇴 화면의 *"기기의 지식은 앱 삭제로만 사라진다"*(§4)와 짝이 맞아야 한다 —
  **앱을 지우기 전에 내보낼 수 있다**는 경로가 이제 생겼다.

## 7. 가드 (`scripts/check-backup.mjs` — 신설 예정)

🔴 **표 목록이 어긋나는 것이 이 기능의 유일한 조용한 실패다.** 표를 하나 추가하고 백업에 안 넣으면
아무 화면도 안 깨지고 아무 테스트도 안 터지는데, **사용자는 기기를 바꾼 뒤에야 안다.**

| 축 | 무엇을 잰다 |
|---|---|
| ① 표 목록 | 파일 형식의 표 배열 == `TABLE_NAMES` − `meta`. 하나라도 다르면 FAIL |
| ② 왕복 | 시드 DB → 내보내기 → 빈 DB 에 가져오기 → **행 단위로 원본과 대조** |
| ③ tombstone | 지운 행이 파일에 있고, 가져온 뒤에도 지워진 채로 있다 |
| ④ 합치기 | `updated_at` 이 큰 쪽이 이긴다(양방향) · 같으면 로컬 유지 |
| ⑤ 거부 | 남의 JSON · `formatVersion` 2 · `schemaVersion` 99 · 20MB 초과 |
| ⑥ SELF-TEST | 위 다섯을 **일부러 깨뜨려** FAIL 이 나는지 먼저 확인한다(exit 2) |

가드가 도는 조건은 지금까지와 같다 — `features/backup/format.ts` 와 병합 규칙을 **순수 모듈**로 두고
`expo-file-system` · `expo-sharing` 은 화면 쪽 얇은 층에만 둔다.
