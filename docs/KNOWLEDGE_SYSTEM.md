## 1. 🔴 저장 흐름 — 이 시스템의 존재 이유

기둥 1: **독서를 방해하지 않는다.** 저장 흐름에 필수 입력을 추가하자는 제안은 전부 여기서 기각한다.

```
앱 열기 → [+] → 원문 입력 또는 촬영 → [저장]
                                        └─ 끝. 책도 안 골라도 된다.
```

### 1.1 필수는 `content` 하나뿐이다

| 필드 | 필수 | 왜 |
|---|---|---|
| 원문(`content`) | **O** | 이게 없으면 지식이 아니다 |
| 책 | ✗ | 🔴 나중에 붙일 수 있다. 지금 고르게 하면 흐름이 끊긴다 |
| 페이지 | ✗ | |
| 내 생각 | ✗ | 기둥 6과 충돌하지 않는다 — **쓰는 자리는 항상 열려 있되 강제하지 않는다** |
| 태그 | ✗ | |

⚠ 저장 후 **"책 연결하기" 유도를 한 번만** 보여준다. 반복하면 그게 곧 필수 입력이 된다.

### 1.2 저장 화면은 앱의 첫 화면에서 1탭 거리다

홈 어디에서도 **최대 1탭**으로 저장에 닿아야 한다. 책 목록 → 책 선택 → 저장은 **경로가 아니다**
(책에서 출발하는 경로는 있어도 되지만 기본 경로가 되면 안 된다).

### 1.3 입력 방식

| 방식 | MVP | 비고 |
|---|---|---|
| 직접 입력 | ✅ | |
| 붙여넣기 | ✅ | 전자책·메모 앱에서 옮겨오는 경로. 실제로 가장 많이 쓰일 수 있다 |
| 사진 → OCR | ✅ | §2 |
| 음성 | 🚫 2차 | |

## 2. OCR

⚠ 엔진 ⚠ 미결정 C. 다만 **방향은 기둥 2에서 도출된다**:

- 🔴 **온디바이스여야 한다.** 책 페이지 사진을 서버로 보내면 "지식이 기기를 떠나지 않는다"가 거짓이 된다.
- 촬영 이미지는 **저장하지 않는다.** 텍스트만 추출하고 이미지는 버린다(사용자가 원문 확인용으로
  남기길 원하면 그때 옵션으로 — v1에는 없다).
- 인식 결과는 **반드시 편집 가능한 상태**로 보여준다. OCR은 틀린다. 틀린 채로 저장되면
  복습 질문까지 오염되고, 그건 사용자가 이유를 알 수 없는 형태로 나타난다.
- 글로벌 출시이므로 **다국어 인식**이 필요하다 — 한국어 전용 엔진은 채택하지 않는다.

## 3. 지식 카드

```
┌────────────────────────────────────┐
│ "목표보다 시스템을 만드는 것이       │   ← content (원문)
│  중요하다."                         │
│                                     │
│ 《아주 작은 습관의 힘》 · 123p        │   ← book · page (없으면 안 보임)
│                                     │
│ ─────────────────────────────────  │
│ 내 생각                             │   ← 기둥 6: 원문과 동등하게 둔다
│ "목표만 세우고 행동하지 않았던        │
│  이유를 생각하게 됐다."              │
│                                     │
│ ─────────────────────────────────  │
│ AI 분석  [CONCEPT]                  │   ← Premium. 없으면 이 블록 자체가 없다
│ 핵심 개념: 시스템 중심 사고           │
│ 주제: 습관 · 목표 · 행동 · 지속성     │
│                                     │
│ 💡 이 내용을 실제 생활에 적용해볼     │   ← actionability = high 일 때만
│    수 있습니다.                      │
│    [실천해보기]  [넘어가기]           │
└────────────────────────────────────┘
```

- 🔴 **AI 분석이 없어도 카드는 완결이다.** 무료 사용자에게 "분석하려면 결제" 자리를 크게 두지 않는다 —
  카드가 미완성으로 보이면 기둥 6("생각을 안 써도 완결")과 함께 무너진다.
- 내 생각은 **여러 개 쌓인다**(1:N). 시간이 지나 다시 읽고 덧붙이는 것이 제품 컨셉이다(기획서 §3).
  UI는 최신 것을 보여주고 나머지는 접는다.

## 4. 책

### 4.1 상태 3종

`wish`(읽고 싶음) → `reading`(읽는 중) → `done`(완료). 되돌릴 수 있다.

⚠ **상태 전이를 자동화하지 않는다.** "지식을 저장했으니 읽는 중으로 바꿔줄까요?" 같은 제안도 v1에는 없다 —
Idea Repository가 같은 종류의 자동 연동을 기획 단계에서 제외했다.

### 4.2 책 상세 = 그 책에서 나온 지식의 중심

```
책 제목
저자                        읽는 중

저장한 지식 18 · 내 생각 7 · 복습 완료 14 · 실천 3
```

🔴 이 숫자들은 **파생값이다. 저장하지 않고 매번 센다**(`DATABASE.md` §4).

### 4.3 🔴 책을 지워도 지식은 남는다

`book_id`를 NULL로 끊을 뿐 캐스케이드 삭제하지 않는다(`DATABASE.md` §3).
**지식은 책보다 오래 남는 것이 이 제품의 전제다.**
삭제 확인 다이얼로그에 "지식 18개는 그대로 남습니다"를 명시한다.

---

### 4.4 독서 진행률 (결정 #17 · 2026-09-09)

**받는 것은 두 값뿐이다** — 총 페이지, 읽은 페이지. 비율은 계산한다.

```
읽는 중          72%
                 ▓▓▓▓▓▓▓░░░   180 / 250쪽
```

- 🔴 **비율을 저장하지 않는다**(`DATABASE.md` §4). 저장하면 두 값과 어긋나는 순간이 오고,
  그때 어느 쪽이 맞는지 판정할 수 없다.
- ⚠ **둘 다 선택 입력이다.** 총 페이지를 모르면 진행률 줄이 **아예 안 보인다** —
  0%로 보여주지 않는다. 0%는 "안 읽었다"이지 "모른다"가 아니다.
- 🚫 **상태를 자동으로 바꾸지 않는다**(§4.1 그대로). 100%가 돼도 `done` 으로 넘기지 않는다 —
  다 읽고도 완료로 두지 않는 사람이 있고, 그건 그 사람의 판단이다.
- 🚫 **독서 목표(주 N권 등)는 넣지 않는다.** 진행률은 현황이고 목표는 압박이다(기둥 5).
- ⚠ 읽은 쪽이 총 쪽보다 크면 **100%로 자른다.** 입력을 막지는 않는다 —
  개정판·전자책에서 쪽수가 어긋나는 일이 실제로 있다.

## 5. 태그

- 사용자가 직접 만든다. **시드 태그를 넣지 않는다** — 우리가 고른 분류가 사용자의 것을 밀어낸다.
- 입력은 칩 방식(공백/쉼표/엔터 확정) + prefix 자동완성(Idea Repository 승계).
- 대소문자 무시 중복 거부. 지식 삭제 시 **고아 태그 정리**(참조 0 → 삭제).
- ⚠ AI가 만든 `topics`는 **태그가 아니다.** 섞으면 사용자의 분류가 AI 출력에 오염된다.
  검색에서는 둘 다 걸리되 저장은 분리한다.

## 6. 검색

MVP는 한 쿼리 LIKE(원문 · 내 생각 · 태그 · 책 제목). 디바운스 **350ms**.
FTS·유사도 검색은 2차(기획서 §24 "기존 지식과의 연결").

### 6.1 네 축 · 결과 단위는 **지식 카드**

| 축 | 어디 |
|---|---|
| 원문 | `knowledge.content` |
| 내 생각 | `thoughts.body` |
| 태그 | `tags.name` |
| 책 제목 | `books.title` |

**어느 한 축이라도 맞으면 그 카드가 나온다.** 결과는 언제나 카드 목록이고, 태그나 책이 아니다.
🔴 **어느 축에서 맞았는지 함께 보여준다.** 원문에 없는 말로 카드가 나오면
사용자는 *"왜 이게 나왔지"* 부터 해석하게 된다. 그건 검색이 아니라 수수께끼다.

### 6.2 🔴 `%` 와 `_` 를 이스케이프한다

SQLite `LIKE` 에서 `%` 는 **아무 문자열**, `_` 는 **아무 한 글자**다.
사용자가 `100%` 를 치면 `%` 가 와일드카드가 되어 **전부 걸린다.** 오류가 안 나고 조용히 틀린다.

```sql
... WHERE content LIKE ? ESCAPE '\'      -- 패턴은 코드에서 만들어 넘긴다
```

- 입력에서 `\` · `%` · `_` 앞에 `\` 를 붙인 뒤 `%…%` 로 감싼다. 순서가 중요하다(`\` 를 먼저).
- ⚠ **책 문장에는 `%` 가 실제로 나온다**(통계·경제서). 가상의 문제가 아니다.
- 가드가 이 축을 잰다(§6.5).

### 6.3 조회 규칙

- 🔴 **네 축 전부 `deleted_at IS NULL`** 이다. 지운 생각으로 지운 카드가 되살아나면 안 된다.
- 🔴 **태그·생각은 조인이 아니라 `EXISTS` 다.** 조인하면 태그 수만큼 카드가 늘어나고,
  그걸 `DISTINCT` 로 접으면 **어느 축에서 맞았는지를 같이 고를 수 없다**(§6.1 이 그걸 요구한다).
  `EXISTS` 는 중복을 애초에 안 만든다. 책 제목만 `LEFT JOIN` 인데 책은 카드당 하나라 늘지 않는다.
- 정렬은 **최근 저장 순**(`created_at DESC`). 🚫 관련도 점수를 만들지 않는다.
  LIKE 에는 점수가 없고, 만들면 그때부터 그 점수를 설명해야 한다.
- 대소문자: SQLite `LIKE` 는 ASCII 만 무시한다. 한국어는 대소문자가 없어 영향이 없다.

### 6.4 빈 검색어

- 공백만 있거나 비어 있으면 **아무것도 조회하지 않는다.** 전체 목록을 뿌리지 않는다.
- 그 자리는 빈 화면이 아니라 **최근 저장**으로 채운다(홈과 같은 원칙 · §7).

### 6.5 가드 — `npm run check:search`

| 축 | 무엇을 잰다 |
|---|---|
| ① 네 축 | 원문·생각·태그·책 제목 각각으로 그 카드가 나오나 |
| ② tombstone | 지운 카드·지운 생각·지운 태그 연결이 결과에 **안 나오나** |
| 🔴 ③ 이스케이프 | **`%` 하나**로 검색했을 때 전부 나오지 않나 · **`_` 하나**로 검색했을 때 0건인가 |
| ④ 중복 | 태그와 원문에 동시에 맞아도 카드가 **한 번만** 나오나 |
| ⑤ 빈 검색어 | 결과가 0건인가(전체를 뿌리지 않나) |
| SELF-TEST | 판정 함수가 살아 있는지 **먼저** 증명한다(exit 2) |

🔴 **③ 을 `100%` 로 재면 아무것도 안 지킨다**(2026-09-10 변이 주입에서 드러났다).
이스케이프를 통째로 걷어내도 패턴이 `%100%%` 가 되어 결국 *"100 이 든 행"* 만 나오므로
검사가 그대로 초록이다. 와일드카드가 새는지를 보려면 **검색어가 와일드카드 하나뿐**이어야 한다.
`%` 하나는 새는 순간 전체를 긁어 오고, `_` 하나는 새는 순간 한 글자 이상인 행 전부를 긁어 온다.
사람이 실제로 치는 `100%` 는 그 옆에 **양성 대조**로 같이 둔다.

### 6.6 화면 (`app/search.tsx`)

```
‹  검색
   [ 검색어                                   ]

   원문                                        ← 맞은 축
   "목표보다 시스템이 중요하다"
   아주 작은 습관의 힘

   내 생각 · 태그
   "환경을 바꾸면 행동이 쉬워진다"
```

- 입력은 **자동 포커스**다. 검색 화면에 들어와서 한 번 더 탭하게 만들지 않는다.
- 디바운스 350ms(§6). 한 글자마다 조회하면 목록이 떨린다.
- 맞은 축은 결과마다 **한 줄로** 보여준다(§6.1). 원문 · 내 생각 · 태그 · 책 순서다.
  기둥 6 이 요구하는 순서이고, 화면과 코드가 같은 배열을 쓴다.
- 🚫 결과 개수를 크게 띄우지 않는다. `12건` 은 성취가 아니다.
- 빈 검색어일 때는 **최근 저장**을 그대로 둔다(§6.4). 빈 화면을 만들지 않는다.
- 결과가 0건일 때만 *"찾는 문장이 없습니다"* 한 줄이다. 🚫 다시 검색하라고 지시하지 않는다.

**진입점은 홈 헤더**다. 🔴 문장이 하나도 없으면 **그리지 않는다**. 검색할 것이 없는 사용자에게
검색 버튼은 기능이 아니라 빈 방으로 가는 문이다(홈의 `책 0 · 문장 0` 을 숨기는 것과 같은 규칙).

## 7. 홈 — "오늘 무엇을 하면 되는가"

🔴 **홈은 책장이 아니다**(기획서 §21).

```
1. 오늘의 복습        ← 가장 위. 개수 + [시작]
2. 오늘의 실천        ← 실천이 있는 사용자에게만
3. 최근 저장한 내용
4. 현재 읽는 책
5. 독서 통계          ← 요약 한 줄. 상세는 별도 화면
```

- 할 일이 **없는 날**의 화면이 중요하다. "복습 0건"을 빈 화면으로 두지 않고
  최근 저장·읽는 책으로 자연스럽게 이어지게 한다.
- 🚫 **스트릭을 끊기지 않게 압박하는 문구를 쓰지 않는다**(기둥 5). 연속일은 보여주되 위협하지 않는다.

## 8. 엣지 케이스 (v1 착수 시 `EDGE_CASES.md`로 이관)

| 상황 | 기대 동작 |
|---|---|
| 원문만 있고 책 없음 | 정상. 카드 목록에 출처 없이 표시 |
