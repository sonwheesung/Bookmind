## 1. 🔴 저장 흐름 — 이 시스템의 존재 이유

기둥 1: **독서를 방해하지 않는다.** 저장 흐름에 필수 입력을 추가하자는 제안은 전부 여기서 기각한다.

```
앱 열기 → [+] → 원문 입력 또는 촬영 → [저장]
                                        └─ 끝. 책도 안 골라도 된다.
```

### 1.1 필수는 `content` 하나뿐이다

| 필드 | 필수 | 왜 |
|---|---|---|
| 원문(`content`) | **O** | 이게 없으면 지식이 아니다 |
| 책 | ✗ | 🔴 나중에 붙일 수 있다. 지금 고르게 하면 흐름이 끊긴다 |
| 페이지 | ✗ | |
| 내 생각 | ✗ | 기둥 6과 충돌하지 않는다 — **쓰는 자리는 항상 열려 있되 강제하지 않는다** |
| 태그 | ✗ | |

⚠ 저장 후 **"책 연결하기" 유도를 한 번만** 보여준다. 반복하면 그게 곧 필수 입력이 된다.

### 1.2 저장 화면은 앱의 첫 화면에서 1탭 거리다

홈 어디에서도 **최대 1탭**으로 저장에 닿아야 한다. 책 목록 → 책 선택 → 저장은 **경로가 아니다**
(책에서 출발하는 경로는 있어도 되지만 기본 경로가 되면 안 된다).

### 1.3 입력 방식

| 방식 | MVP | 비고 |
|---|---|---|
| 직접 입력 | ✅ | |
| 붙여넣기 | ✅ | 전자책·메모 앱에서 옮겨오는 경로. 실제로 가장 많이 쓰일 수 있다 |
| 사진 → OCR | ✅ | §2 |
| 음성 | 🚫 2차 | |

## 2. OCR

⚠ 엔진 ⚠ 미결정 C. 다만 **방향은 기둥 2에서 도출된다**:

- 🔴 **온디바이스여야 한다.** 책 페이지 사진을 서버로 보내면 "지식이 기기를 떠나지 않는다"가 거짓이 된다.
- 촬영 이미지는 **저장하지 않는다.** 텍스트만 추출하고 이미지는 버린다(사용자가 원문 확인용으로
  남기길 원하면 그때 옵션으로 — v1에는 없다).
- 인식 결과는 **반드시 편집 가능한 상태**로 보여준다. OCR은 틀린다. 틀린 채로 저장되면
  복습 질문까지 오염되고, 그건 사용자가 이유를 알 수 없는 형태로 나타난다.
- 글로벌 출시이므로 **다국어 인식**이 필요하다 — 한국어 전용 엔진은 채택하지 않는다.

## 3. 지식 카드

```
┌────────────────────────────────────┐
│ "목표보다 시스템을 만드는 것이       │   ← content (원문)
│  중요하다."                         │
│                                     │
│ 《아주 작은 습관의 힘》 · 123p        │   ← book · page (없으면 안 보임)
│                                     │
│ ─────────────────────────────────  │
│ 내 생각                             │   ← 기둥 6: 원문과 동등하게 둔다
│ "목표만 세우고 행동하지 않았던        │
│  이유를 생각하게 됐다."              │
│                                     │
│ ─────────────────────────────────  │
│ AI 분석  [CONCEPT]                  │   ← Premium. 없으면 이 블록 자체가 없다
│ 핵심 개념: 시스템 중심 사고           │
│ 주제: 습관 · 목표 · 행동 · 지속성     │
│                                     │
│ 💡 이 내용을 실제 생활에 적용해볼     │   ← actionability = high 일 때만
│    수 있습니다.                      │
│    [실천해보기]  [넘어가기]           │
└────────────────────────────────────┘
```

- 🔴 **AI 분석이 없어도 카드는 완결이다.** 무료 사용자에게 "분석하려면 결제" 자리를 크게 두지 않는다 —
  카드가 미완성으로 보이면 기둥 6("생각을 안 써도 완결")과 함께 무너진다.
- 내 생각은 **여러 개 쌓인다**(1:N). 시간이 지나 다시 읽고 덧붙이는 것이 제품 컨셉이다(기획서 §3).
  UI는 최신 것을 보여주고 나머지는 접는다.

## 4. 책

### 4.1 상태 3종

`wish`(읽고 싶음) → `reading`(읽는 중) → `done`(완료). 되돌릴 수 있다.

⚠ **상태 전이를 자동화하지 않는다.** "지식을 저장했으니 읽는 중으로 바꿔줄까요?" 같은 제안도 v1에는 없다 —
Idea Repository가 같은 종류의 자동 연동을 기획 단계에서 제외했다.

### 4.2 책 상세 = 그 책에서 나온 지식의 중심

```
책 제목
저자                        읽는 중

저장한 지식 18 · 내 생각 7 · 복습 완료 14 · 실천 3
```

🔴 이 숫자들은 **파생값이다. 저장하지 않고 매번 센다**(`DATABASE.md` §4).

### 4.3 🔴 책을 지워도 지식은 남는다

`book_id`를 NULL로 끊을 뿐 캐스케이드 삭제하지 않는다(`DATABASE.md` §3).
**지식은 책보다 오래 남는 것이 이 제품의 전제다.**
삭제 확인 다이얼로그에 "지식 18개는 그대로 남습니다"를 명시한다.

## 5. 태그

- 사용자가 직접 만든다. **시드 태그를 넣지 않는다** — 우리가 고른 분류가 사용자의 것을 밀어낸다.
- 입력은 칩 방식(공백/쉼표/엔터 확정) + prefix 자동완성(Idea Repository 승계).
- 대소문자 무시 중복 거부. 지식 삭제 시 **고아 태그 정리**(참조 0 → 삭제).
- ⚠ AI가 만든 `topics`는 **태그가 아니다.** 섞으면 사용자의 분류가 AI 출력에 오염된다.
  검색에서는 둘 다 걸리되 저장은 분리한다.

---

## 6. 검색

MVP는 한 쿼리 LIKE(원문 · 내 생각 · 태그 · 책 제목). 디바운스 300~500ms.
FTS·유사도 검색은 2차(기획서 §24 "기존 지식과의 연결").

---

## 7. 홈 — "오늘 무엇을 하면 되는가"

🔴 **홈은 책장이 아니다**(기획서 §21).

```
1. 오늘의 복습        ← 가장 위. 개수 + [시작]
2. 오늘의 실천        ← 실천이 있는 사용자에게만
3. 최근 저장한 내용
4. 현재 읽는 책
5. 독서 통계          ← 요약 한 줄. 상세는 별도 화면
```

- 할 일이 **없는 날**의 화면이 중요하다. "복습 0건"을 빈 화면으로 두지 않고
  최근 저장·읽는 책으로 자연스럽게 이어지게 한다.
- 🚫 **스트릭을 끊기지 않게 압박하는 문구를 쓰지 않는다**(기둥 5). 연속일은 보여주되 위협하지 않는다.

## 8. 엣지 케이스 (v1 착수 시 `EDGE_CASES.md`로 이관)

| 상황 | 기대 동작 |
|---|---|
| 원문만 있고 책 없음 | 정상. 카드 목록에 출처 없이 표시 |
| 같은 문장을 두 번 저장 | 허용. 🔴 중복 검사를 넣지 않는다 — 기둥 1(흐름 차단 금지) |
| OCR이 빈 문자열 반환 | 저장 버튼 비활성 + 직접 입력으로 유도. 빈 카드가 생기면 안 된다 |
| 원문이 매우 길다(한 챕터 붙여넣기) | 허용하되 AI 분석 시 길이 상한(§AI_SYSTEM)에 걸린다 — 그때 안내 |
| 책을 지웠는데 그 책의 지식에 실천이 달려 있음 | 실천 유지. `knowledge_id`는 살아 있다 |
| 기기 언어 ko · 원문 en | 원문은 en 그대로 보관. AI 응답 언어는 설정을 따른다(§I18N) |
