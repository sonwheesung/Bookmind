## 1. 🔴 회상은 채점이 아니다

기둥 5: **시험 앱이 아니다.**

```
① 질문을 먼저 보여준다          "저자가 강조한 핵심은 무엇이었나요?"
② 사용자가 떠올린다             (입력은 선택 — 안 써도 넘어갈 수 있다)
③ 원문 · 요지를 공개한다
④ 사용자가 스스로 고른다        [안 떠올랐다] [겨우 떠올랐다] [떠올랐다] [바로 떠올랐다]
                                    ↓
                                FSRS 등급 (again/hard/good/easy)
```

- 🚫 **정답 문자열 비교를 하지 않는다.** 그래서 `recall_questions`에 정답 컬럼이 없다
  (`DATABASE.md` §2). `expected_point`는 "이런 걸 떠올렸으면 좋겠다"의 요지일 뿐이다.
- 🚫 점수·등급·정답률을 사용자에게 성적표로 돌려주지 않는다. 통계의 "기억률"은
  **성취 지표가 아니라 현황**으로 보여준다.
- 사용자가 적은 답변(`review_logs.answer_text`)은 **자산이다.** 나중에 자기 답변의 변화를
  보는 것이 이 앱의 가치가 된다 — 지우지 않는다.

### 1.1 🔴 4등급 버튼에 **다음 복습 시점을 적지 않는다** (2026-09-09 확정)

ChatGPT 시안이 버튼마다 `더 자주 / 조금 더 / 조금 더 뒤에 / 한참 뒤` 를 붙여 왔다.
**형식은 채택하고 내용은 기각한다** — 같은 자리에 **기억이 언제 돌아왔는지**를 적는다(`DESIGN_REVIEW.md` §3).

🔴 **`CLAUDE.md` §5 규칙 8 이 금지한 것이 아니다.** 규칙 8 은 `difficulty`·`stability` 를 금지하고
*"화면에 나가는 것은 **다음 복습 시점**까지다"* 라고 **허용의 상한을 명시**한다. 기각 근거는 둘이다:

- 🚫 **선택 전에 보여주면 등급이 회상 보고가 아니라 스케줄 다이얼이 된다.** 기둥 5 는 회상 결과를
  *"다음 노출 시점을 정하는 **입력값일 뿐**"* 이라 못박았고 §5 규칙 4 는 사용자가 **자기 기억을** 고른다고 했다.
  스케줄을 먼저 보여주면 화살표가 뒤집혀 **FSRS 의 입력이 회상 데이터가 아니게 된다** —
  §3.1 이 기록한 오염 경로(단서 부족 → [안 떠올랐다] → 간격이 계속 짧아짐)의 **반대 방향**이다.
  ⚠ 두 방향은 대칭이 아니다. `안 떠올랐다` 남용은 시간만 쓰지만 `바로 떠올랐다` 남용은 간격을 **19일 → 77일**로 튀게 해
  **기둥 7 이 사용자 손으로 깨진다.**
- 🚫 **우리는 그 값을 아직 진실하게 말할 수 없다.** FSRS 의 `due_at` 은 사용자가 실제로 다시 보는 시점이
  **아니다**: 큐 판정이 날 단위(`due_at < 로컬 자정`, §2.1)이고, 세션 큐는 고정되며, 하루 상한 20(§2.2)이
  또 뒤로 민다. `10분 후` 라고 적으면 **거짓이 된다.**

**실측 (2026-09-09 · `ts-fsrs` 기본 `learning_steps: ["1m","10m"]`)**

| 노출 | state | 안 떠올랐다 | 겨우 | 떠올랐다 | 바로 |
|---|---|---|---|---|---|
| #1 (새 카드) | new | 1분 | 6분 | 10분 | 8.0일 |
| #2 | learning | 1분 | 6분 | 2.0일 | 4.0일 |
| #3 | review | 10분 | 8.0일 | 11.0일 | 19.0일 |
| #4 | review | 10분 | 32일 | 46일 | 77일 |

🔴 **새 카드의 앞 세 개는 전부 분 단위다.** 이걸 "더 자주"라고 적는 것은 정확하지 않고,
기획서 §15 의 `1/3/7/14/30/90`(사용자 설명용 근사, §2)이 만든 기대와도 어긋난다.

**대신 적는 것 — 스케줄이 아니라 회상의 난이도**

🔄 **2026-09-09 재결정: 부가 설명을 따로 두지 않고 라벨 자체를 바꿨다**(`review.ratingHint.*` 는 만들지 않는다).
~~`잊었다` + 부제 `안 떠올랐다`~~ 처럼 두 줄로 두면 **같은 말을 두 번 하는 버튼**이 된다 —
아래 규칙("라벨과 같은 말을 되풀이하지 않는다")을 부제 설계 자신이 어기고 있었다.

| FSRS | 라벨 ko | 라벨 en |
|---|---|---|
| `again` | 안 떠올랐다 | I couldn't recall it |
| `hard` | 겨우 떠올랐다 | It barely came back |
| `good` | 떠올랐다 | It came back |
| `easy` | 바로 떠올랐다 | It came back right away |

- 🚫 **`보고서야 떠올랐다` 를 쓰지 않는다**(문구 검수 제안 · 기각). 우리 화면은 **원문을 공개한 뒤에**
  등급을 고르므로 *"보고서야"* 는 **네 버튼 전부에 해당한다** — 가르는 말이 못 된다.
  게다가 뜻으로는 `again`(못 떠올림)에 더 가까워 `hard` 자리에 놓으면 FSRS 입력이 흐려진다.
- 🚫 ~~`쉽다`~~ 도 안 쓴다. 문제의 난이도를 평가하는 말이라 시험 앱이 된다(문구 검수 채택).
- 🟢 **스케줄 정보가 0이라 게임할 기울기가 없다.** 그런데 네 버튼의 차이는 매번 보인다 —
  최초 1회 안내는 3주 뒤에 돌아온 사용자에게 이미 없는 정보이고, "봤음" 플래그라는 상태가 하나 는다.
- 가르는 축은 **노력**이다(안 떠올랐다 → 겨우 → 그냥 → 바로). 버튼 위에는 `review.howRecalled`
  *"어떻게 떠올랐나요?"* 하나만 둔다.

**다시 열 조건**: 다음 복습 시점을 화면에 쓰고 싶어지면 두 가지를 **먼저** 갖춘다 —
① 선택 **후** 통지일 것 ② 보여주는 값이 FSRS 의 `due_at` 이 아니라 **큐가 실제로 띄울 날짜**일 것.
⚠ 통지도 두 세션이면 매핑이 학습되므로 **날짜 하나만**, 비교어 없이.

### 1.2 🔴 학습 단계를 안 들고 다녀 간격이 안 자라던 결함 (2026-09-09 · v3 로 고침)

위 실측표의 노출 #2 이후 값은 **"정상 동작 시"의 값**이다. 발견 당시 실제 코드는 이랬다:

```
노출 1  new        떠올랐다 → 10분
노출 2  learning   떠올랐다 → 10분      ← 정상이면 2.0일, review 로 졸업
노출 6  learning   떠올랐다 → 10분      ← 영원히 learning
```

원인: `ts-fsrs` 카드의 **`learning_steps`(지금 몇 번째 학습 단계인가)** 를 `review_schedules` 가
들고 다니지 않아 매번 0 으로 리셋됐다. 🔴 **[떠올랐다]만 누르는 사용자의 카드는 간격이 절대 자라지 않는다** —
탈출구가 [바로 떠올랐다]뿐이라, "잊을 때쯤 다시 만난다"(기둥 7)가 **반대로 작동**하고 있었다.

⚠ **`check:review` 는 그때도 초록이었다.** 한 시점의 단조성(`again < hard < good < easy`)과 `lapses` 증가만
재고 **반복 노출**을 안 봤기 때문이다. → 가드에 *"여섯 번 눌러 `review` 로 졸업하고 간격이 단조 증가하는가"* 를
넣었고, 변이(값을 다시 안 들고 다니게)로 FAIL 을 확인했다.
★ `I18N_SYSTEM.md` §5.1 의 *"개수는 실행량이지 검증량이 아니다"* 가 다른 얼굴로 또 나왔다.

## 2. 스케줄 — FSRS

**결정 #5 (2026-09-08)**: `ts-fsrs` 기본 파라미터.

- 기획서 §15의 `1일 → 3일 → 7일 → 14일 → 30일 → 90일`은 🔴 **사용자 설명용 근사**이지 구현 스펙이 아니다.
  실제 간격은 FSRS가 `stability`·`difficulty`에서 계산한다. **문서·UI에 고정 간격표를 스펙처럼 쓰지 않는다.**
- 왜 고정 간격표가 아니라 FSRS인가: 구현 비용이 비슷한데 결과가 낫고, **개인화(optimizer)로 가는 길이
  이미 나 있다**(기획서 §15의 최종 목표). 고정 간격으로 시작하면 그 전환이 마이그레이션이 된다.
- `review_logs`에 `elapsed_days`·`scheduled_days`를 남기는 이유가 이것이다 — v1.2 optimizer의 유일한 입력.

### 2.1 "하루"의 경계

🔴 **기기 로컬 자정 고정.** `due_at`은 UTC로 저장하지만 "오늘의 복습"은 로컬 자정 기준으로 센다.
로케일을 따르지 않는다(주 시작 요일 같은 것에 흔들리면 복습 큐가 날마다 달라진다).

### 2.2 큐가 폭발하는 날

며칠 앱을 안 열면 밀린 카드가 한꺼번에 뜬다. 기둥 5(압박하지 않는다)와 정면으로 부딪힌다.

- **하루 상한을 둔다.** 밀린 것은 오래된 순으로 상한까지만 보여주고 나머지는 조용히 다음 날로.
- 🚫 "37개가 밀렸습니다"를 크게 띄우지 않는다. 그건 앱을 여는 것 자체를 부담으로 만든다.
- **상한값 = 20** (2026-09-09 Phase 3 착수에서 확정). 출발값 그대로 간다.
  🔴 **근거는 "적당해서"가 아니라 이 앱의 카드 한 장이 무겁기 때문이다** —
  회상은 떠올리는 시간이 있고, 원문은 책 문장이라 길다. 20장이면 한 세션 5~10분이고
  그보다 길면 "오늘은 안 열래"가 된다(기둥 5와 같은 축).
  ⚠ 이 값은 **실사용 전에는 검증 불가**다. Phase 10(무료 한도)과 함께 다시 본다.

### 2.3 🔴 새 카드는 **다음 날부터** 큐에 뜬다 (2026-09-09 확정)

저장한 그 날은 안 뜬다. 방금 읽은 문장을 몇 분 뒤에 다시 보여주는 것은 회상이 아니라 **되읽기**다.

```
저장 → review_schedules 행을 그 자리에서 만든다(state='new')
       due_at = 저장한 날의 **다음 로컬 자정**
```

- 🔴 저장 시점에 행을 만든다 — 나중에 "스케줄 없는 카드"를 찾아 채우는 배치를 만들지 않는다.
  그 배치는 빠뜨리면 **카드가 영원히 큐에 안 뜨는** 형태로 조용히 실패한다.
- "오늘의 복습" 판정은 `due_at < 내일 로컬 자정` 이다(§2.1). UTC 로 저장하고 **비교는 로컬 자정으로 환산**한다.
- ⚠ 그래서 **밤 11시에 저장하면 한 시간 뒤에 뜬다.** 정상이다 — 경계는 시각이 아니라 날짜다.

## 3. 🔴 두 층의 복습 — 무료에서도 성립한다

**결정 #9 (2026-09-08)**: 복습이 Premium 전용이 되면 기둥 7이 깨진다.

| | 기본 복습 (무료) | AI 회상 (Premium) |
|---|---|---|
| 질문 | 없음 — **원문을 가리고 출처·내 생각만 보여준다** | AI가 만든 5종 중 순환 |
| 사용자 행동 | 떠올린 뒤 [공개] | 질문에 답한 뒤 [공개] |
| 스케줄 | 동일 FSRS | 동일 FSRS |
| 오프라인 | ✅ | ✅ (질문이 로컬에 있다) |

**기본 복습의 화면**:

```
《아주 작은 습관의 힘》 · 123p
3일 전에 저장한 내용입니다.

내 생각
"목표만 세우고 행동하지 않았던 이유를 생각하게 됐다."

┌──────────────────────────┐
│   원문을 떠올려 보세요      │
│        [공개하기]          │
└──────────────────────────┘
```

🔴 내 생각을 단서로 주는 것이 핵심이다 — 원문만 가리면 그냥 빈칸 채우기가 되고,
내 생각을 남긴 사용자는 **자기 언어로 저장한 맥락**에서 원문을 떠올리게 된다(기둥 6).

### 3.1 🔴 단서가 하나도 없는 카드 — 기본 저장 카드의 복습 화면 (2026-09-09 확정)

위 화면은 **책·페이지·내 생각을 단서로 쓴다.** 그런데 기둥 1이 만드는 **기본 산출물은 원문 하나뿐인 카드**다
(책도 생각도 없다). 그 카드에 위 화면을 그대로 쓰면 *"원문을 떠올려 보세요"* 만 남은 **빈 상자**가 된다
(2026-09-08 이탈·정합 심사가 함께 지적, `PLAN.md` Phase 3).

**단서를 무엇으로 채우나 — 있는 것부터 순서대로 쓴다:**

| 순위 | 단서 | 있을 때 |
|---|---|---|
| 1 | 내 생각(최신 1건) | 가장 좋은 단서. 기둥 6 |
| 2 | 책 · 페이지 | 출처가 맥락이 된다 |
| 3 | 태그 | 사용자가 스스로 붙인 분류다 |
| 4 | 🔴 **첫 몇 글자 + 저장 시점** | **위가 전부 없을 때.** 아래 참조 |

🔄 **글자 수를 12 → 8 로 줄였다 (2026-09-09 · 우리 결정을 되돌림).**
처음에 12자로 정한 근거는 *"너무 짧으면 막막하다"* 뿐이었고 **반대쪽 위험을 안 봤다** —
`9월 10일 / Systems beat goals…` 정도면 문장을 거의 알아본다. 그러면 **회상이 아니라 인식**이 되고,
회상 난이도를 재는 등급이 전부 [떠올랐다] 쪽으로 쏠린다. 단서는 **맞히는 힌트가 아니라
기억을 꺼내는 트리거**여야 한다(ChatGPT 검수 · `DESIGN_REVIEW.md` §3).

```
2026년 9월 6일에 저장했습니다.          ← 언제나 있다
"목표보다 시…"                          ← 원문 앞 8자 + 말줄임
        [공개하기]
```

- 🔴 **앞 8자를 주는 것이 이 절의 결정이다.** 아무 단서도 없이 "떠올려 보세요"는 회상이 아니라 **막막함**이고,
  그 카드는 사용자가 [안 떠올랐다]를 누르고 끝낸다 — 그러면 FSRS 가 *"이 사람은 이 카드를 못 외운다"* 로 학습해
  **간격이 계속 짧아진다.** 단서 부족이 데이터 오염으로 번지는 경로다.
- 🚫 앞 글자를 **길게 주지 않는다.** 절반을 보여주면 회상이 아니라 읽기가 된다.
  ⚠ 한국어·영어·일본어가 섞이므로 **글자 수를 언어별로 맞추려 하지 않는다** — 한 값으로 둔다.
- ⚠ 원문이 8자보다 짧으면 **단서를 아예 주지 않는다**(다 보여주게 되므로). 그때는 저장 시점만 남는다.

## 4. AI 회상 질문 5종

기획서 §16. 생성·프롬프트는 [`AI_SYSTEM.md`](./AI_SYSTEM.md).

| kind | 무엇을 묻나 | 어느 유형에 잘 맞나 |
|---|---|---|
| `recall` 기억 | 이 내용의 핵심은 무엇이었나요? | FACT · CONCEPT |
| `understand` 이해 | 저자는 왜 이런 주장을 했을까요? | CONCEPT · OPINION |
| `perspective` 관점 | 이 주장에 반대한다면 어떤 근거를 들 수 있을까요? | OPINION |
| `experience` 경험 | 자신의 경험 중 비슷한 사례가 있었나요? | INSIGHT · ACTION |
| `apply` 적용 | 지금 생활에 적용한다면 어떻게 할 수 있을까요? | ACTION |

- 🔴 **저장 시 1회 생성해 로컬에 보관한다**(결정 #4). 복습마다 AI를 부르지 않는다 —
  비용이 복습 횟수에 비례해 터지고, **오프라인에서 복습이 안 된다.**
  대가: 질문이 고정된다. 다양화·재생성은 2차.
- 복습 회차마다 **다른 kind를 순환**시킨다. 같은 질문이 반복되면 답을 외워버려 회상이 아니게 된다.
- 유형에 안 맞는 kind는 건너뛴다(FACT에 `perspective`를 묻지 않는다). AI가 생성 단계에서
  해당 카드에 맞는 것만 만들도록 하고, **5종을 억지로 채우지 않는다.**

## 6. 🔴 알림 — 이 앱 최대의 단일 위험

로컬 정본이므로 **서버가 무엇을 복습해야 하는지 모른다.** 서버 푸시가 원천적으로 불가능하고,
`expo-notifications`의 **로컬 알림**이 유일한 도달 수단이다. 이게 로컬 정본의 대가다.

### 6.1 조용히 죽는 방식들

| 원인 | 증상 | 대응 |
|---|---|---|
| Android 배터리 최적화 · Doze | 알림이 몇 시간~며칠 지연되거나 안 옴 | 설정에서 예외 요청 안내(강요하지 않음) |
| 앱 강제 종료(스와이프) | 예약된 알림이 취소되는 기기가 있다(제조사별) | 부팅 시 재예약 |
| 재부팅 | 예약 소실 | `BOOT_COMPLETED` 재예약 |
| 🔴 `prebuild` 미실행 | **알림 아이콘이 흰 사각형 덩어리** | §6.3 |

🔴 **크래시가 아니라 "안 오는 것"이라 사용자도 우리도 모른다.**
그래서 Phase 4 완료 기준에 **실기기 다일차 검증**을 넣는다(하루짜리 테스트로는 안 잡힌다).

### 6.2 예약 정책

- 사용자가 시각을 하나 고른다(기본값 ⚠ 미결정 — 출발값 21:00 로컬).
- 그날 복습할 것이 **있을 때만** 보낸다. 0건인 날 알림은 신뢰를 깎는다.
- 하루 1회. 🚫 여러 번 찌르지 않는다(기둥 5).
- 알림을 끈 사용자에게 다시 켜라고 반복 요청하지 않는다.

#### 🔴 6.2.1 "있을 때만"을 로컬 알림으로 어떻게 하나 (2026-09-09 확정)

**로컬 알림은 발송 시점에 코드를 돌리지 못한다.** 조건을 붙일 수 있는 순간은 **예약할 때**뿐이다.
그래서 **앞으로 N일치를 미리 계산해 예약**하고, 앱이 열릴 때마다 다시 계산해 덮어쓴다.

```
planReminders({ dueAts, now, time, days: 7 })
  → 오늘부터 7일, 각 날의 알림 시각(로컬)을 만든다
  → 이미 지난 시각은 버린다
  → 그 날의 **자정 경계**(§2.1 과 같은 기준)까지 만기가 오는 카드가 하나라도 있으면 그 날을 넣는다
```

- 🟢 **밀린 카드는 사라지지 않으므로** 한 번 만기가 오면 그 뒤 날들도 전부 해당된다 —
  즉 "첫 만기일부터 7일"이 예약된다. 사용자가 복습하면 다음 실행에서 다시 계산돼 줄어든다.
- 🔴 **7일은 "앱을 안 여는 동안"의 예산이다.** 8일 넘게 앱을 안 열면 알림이 끊긴다.
  그건 우리가 못 고치는 것이 아니라 **로컬 알림의 성질**이고, 그때는 이미 제품이 실패한 상태다.
  ⚠ 이 한계를 "무한 반복 예약"으로 덮지 않는다 — 만기가 없는 날에도 찌르게 되어 위 규칙이 깨진다.
- 다시 계산하는 시점: 앱 포그라운드 · 복습 한 장을 마칠 때 · 설정에서 켜고 끌 때.
- 🚫 예약 개수가 늘지 않게 **매번 전부 취소하고 다시 넣는다.** 누적되면 하루에 여러 번 울린다.

### 6.3 🔴 네이티브 리소스 함정 (My Word 실증, 승계)

`expo-notifications`의 config plugin은 **`prebuild`를 돌려야 실행된다.** `android/`를 커밋하지 않고
CNG로 가더라도, 아래가 없으면 **알림 아이콘이 흰 사각형**이 된다:

```
AndroidManifest.xml   expo.modules.notifications.default_notification_icon · _color
res/drawable-*/       notification_icon.png (5종, 24dp×배율 흰 실루엣)
res/values/colors.xml notification_icon_color
```

⚠ `app.json`의 plugins 항목만 보고 "설정했다"고 판단하면 안 된다. **실제 파일 존재를 확인한다.**

#### 🔴 6.3.1 실측 — 함정이 실재했다 (2026-09-09)

`app.json` 의 `plugins` 에 `expo-notifications` 를 넣고 `npx expo prebuild --platform android` 를 돌려
**생성된 파일을 직접 셌다.** 결과는 셋 다 0건이다.

| §6.3 이 요구한 것 | 실측 |
|---|---|
| `AndroidManifest.xml` 의 `default_notification_icon` · `_color` | 🔴 **0건** |
| `res/drawable-*/notification_icon.png` | 🔴 **0건**(폴더는 있고 그 파일만 없다) |
| `res/values/colors.xml` 의 `notification_icon_color` | 🔴 **없다**(`splashscreen_background`·`colorPrimary` 만) |

🔴 **원인은 `prebuild` 를 안 돌린 것이 아니었다.** 돌렸는데도 안 생긴다 —
플러그인을 **옵션 없이** 넣으면 만들지 않고, `icon`·`color` 를 줘야 그때 생성한다.

```jsonc
// 이렇게 써야 리소스가 생긴다
["expo-notifications", { "icon": "./assets/notification-icon.png", "color": "#3A5A73" }]
```

✅ **2026-09-09 같은 날 닫혔다.** 아이콘 넉 장을 만들고(`scripts/make-icons.mjs`) `app.json` 에 물린 뒤
`prebuild` 를 다시 돌려 **세 축이 전부 생성되는 것을 확인**했다.

```
AndroidManifest  expo.modules.notifications.default_notification_icon · _color   ✅
res/drawable-*   notification_icon.png  5종(mdpi~xxxhdpi)                        ✅
res/values       colors.xml 의 notification_icon_color = #3A5A73                 ✅
```

🟢 적응형 아이콘의 `monochrome` 레이어도 함께 붙었다(Android 13+ 테마 아이콘).
⏸ 남은 것은 **기기에서 눈으로 보는 것**이다 — 리소스가 있다는 것과 24dp 에서 알아볼 수 있다는 것은 다른 축이다.

⚠ `android/` 는 확인 뒤 지웠다. CNG 산출물이라 남기면 `app.json` 과 어긋난 채 다음 세션을 속인다.

### 6.4 실측 — Expo Go 에서 어디까지 되나 (2026-09-09 · AVD `reread` · Android 15)

착수 전에 재기로 한 것을 쟀다. **결론: 로컬 알림은 Expo Go 에서 그대로 된다.**

| 무엇 | 결과 |
|---|---|
| 권한 요청 | 뜬다. 거절하면 스위치를 도로 끄고 안내 문구로 바꾼다 |
| 채널 생성(`review`) | 된다. 🔴 안드로이드는 채널이 없으면 **조용히 안 뜬다** |
| 예약 | `dumpsys alarm` 에 `expo.modules.notifications.NOTIFICATION_EVENT` RTC_WAKEUP 이 **날짜별 1건씩** |
| 발송 | 🟢 **도달했다.** 시계를 21:00 으로 넘기니 *"오늘의 복습 / 다시 만날 문장이 있습니다."* |
| 취소 | 스위치를 끄면 21:00 알람이 **0건**이 된다 |
| 🚫 푸시 | Expo Go 는 Android 푸시를 뺐다(경고 토스트가 뜬다). **우리는 안 쓴다** — 서버가 무엇을 복습해야 하는지 모른다 |
| ⚠ 아이콘 | Expo Go 의 아이콘으로 뜬다. **우리 아이콘은 아직 확인 못 했다** — §6.3 의 자리는 그대로 열려 있다 |

🔴 **`prebuild` 없이 잰 것이라 §6.3 은 닫히지 않았다.** dev/릴리스 빌드에서 다시 봐야 한다.

### 6.5 🔴 예약이 두 배가 되던 결함 (2026-09-09 · 실측에서 잡음)

처음 켰을 때 7일치가 **14건**으로 들어갔다. `dumpsys alarm` 을 보기 전에는 아무 표시도 없었다.

```
설정 스위치를 켠다
  ① toggleReminder() 가 syncReminders 를 부른다
  ② enabled 가 바뀌어 useReminderSync 의 effect 도 부른다
둘이 같이 출발 → cancelOurs() 가 둘 다 **빈 목록**을 본다 → 각자 7건씩 넣는다
```

🔴 **취소 로직이 있어도 못 막는다.** 취소할 시점에 아직 아무것도 없기 때문이다.
→ `syncReminders` 를 **줄 세운다**(앞 호출이 끝나야 다음이 출발한다). 다시 재서 7일 → 7건 확인.

⚠ 이건 "하루 1회"(§6.2)를 깨는 결함이고, **화면으로는 절대 안 보인다.**
알림은 도달했는지조차 사용자가 말해 주지 않으므로 **기기 상태를 직접 읽는 것 말고 확인할 방법이 없다.**

## 7. 통계와의 관계

- **기억률** = `review_logs` 중 `rating != 'again'` 비율. 🔴 파생값이므로 저장하지 않고 매번 센다.
- **연속 학습일** = 복습 또는 저장 활동이 있는 날의 연속. 실천 체크와 **별도로 센다**
  (실천이 없는 사용자도 연속일을 가진다).
- 🚫 기억률을 낮다고 경고하거나 목표를 제시하지 않는다(기둥 5).

## 8. 엣지 케이스 (v1 착수 시 `EDGE_CASES.md`로 이관)

| 상황 | 기대 동작 |
|---|---|
| AI 분석 없는 카드가 복습 큐에 옴 | 기본 복습(원문 가리기)으로 진행. 🔴 건너뛰지 않는다 |
| Premium 해지 후 복습 | AI 질문은 이미 로컬에 있다 → **계속 쓸 수 있다.** 새 분석만 막힌다 |
| 시간대를 바꾼 채로 여행 | 로컬 자정 기준이라 하루가 짧아지거나 길어진다. 큐만 다시 계산, 스케줄은 그대로 |
| 지식을 지웠는데 복습 큐에 남음 | `deleted_at IS NULL` 필터 누락 버그. 🔴 헬퍼로 강제(`DATABASE.md` §1.1) |
| 밀린 카드 200개 | 하루 상한까지만 노출(§2.2). 나머지는 조용히 |
| 회상 답변을 안 쓰고 [공개] | 정상. 입력은 선택이다 |
| 🔴 **책·생각·태그가 전부 없는 카드** | §3.1 — 저장 시점 + 원문 앞 12자를 단서로 준다. **빈 상자를 보여주지 않는다** |
| 원문이 8자 이하인 카드 | 앞 글자 단서를 **생략**한다(다 보여주게 된다). 저장 시점만 |
| 저장한 날 복습 큐를 열었다 | 방금 저장한 카드는 **안 뜬다**(§2.3 — 다음 날부터). 되읽기는 회상이 아니다 |
| 밤 11시에 저장하고 자정에 열었다 | 뜬다. 경계는 시각이 아니라 **날짜**다(§2.3) |
