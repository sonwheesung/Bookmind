## 1. 🔴 실천은 사용자가 문장을 확정해야 생긴다

기둥 3: **AI는 제안하고 사용자가 정한다.**

```
지식 카드
  actionability = 'high'
        ↓
  💡 이 내용을 실제 생활에 적용해볼 수 있습니다.
     [실천해보기]        [넘어가기]
        ↓                    ↓
  실천 문장 편집 화면      끝. 🔴 같은 카드에 다시 묻지 않는다
  (AI 제안이 미리 채워짐)
        ↓
  사용자가 고쳐서 [만들기]
        ↓
  practices 행 생성
```

- 🔴 **AI 제안 문장을 그대로 쓰더라도 사용자가 [만들기]를 눌러야 생성된다.** 자동 생성은 없다.
- 🔴 **[넘어가기]는 영구적이다.** 같은 카드가 복습에 다시 떠도 실천 제안을 반복하지 않는다.
  반복하면 그건 제안이 아니라 압박이다.
- 원래 지식과 사용자의 실천은 **다른 문장이어도 된다**(기획서 §12):
  > 지식: "환경을 바꾸면 행동을 바꾸기 쉽다."
  > 실천: "자기 전에 스마트폰을 책상 위에 놓는다."

### 1.1 🔴 [넘어가기]를 어디에 적나 (2026-09-10)

§1 은 *"[넘어가기]는 영구적이다"* 라고 2026-09-08 부터 적어 뒀는데, **그걸 적을 칸이 스키마에 없었다.**
Phase 9 착수 전 대조에서 나왔다. 규칙만 있고 저장할 자리가 없으면 그 규칙은 코드에서 조용히 사라진다.

```sql
-- v5
ALTER TABLE knowledge ADD COLUMN practice_skipped_at TEXT;
```

| 값 | 뜻 |
|---|---|
| NULL | 아직 안 물어봤거나, 물어봤는데 **만들었다** |
| 시각 | 사용자가 [넘어가기]를 눌렀다. 🔴 **다시 묻지 않는다** |

- 🔴 **표를 따로 만들지 않고 컬럼으로 둔 이유**: 이 값은 카드 한 장에 하나뿐이고,
  카드가 지워지면 함께 지워져야 하며, 백업에서 카드가 돌아오면 **그 결정도 함께 돌아와야** 한다.
  컬럼이면 셋이 공짜로 성립한다. 표를 만들면 셋 다 우리가 배선해야 한다.
- 🚫 **[넘어가기]가 실천 생성을 막는 것은 아니다.** 막는 것은 **제안 배너**뿐이다.
  사용자가 나중에 그 카드에서 직접 실천을 만들려 하면 그건 그대로 된다(기둥 3 은 제안을 제한하지 사용자를 제한하지 않는다).

## 2. 실천 설정

| 항목 | 필수 | 설명 |
|---|---|---|
| 실천 이름(`title`) | O | 사용자가 확정한 문장 |
| 시작일(`started_at`) | O | 기본값 오늘 |
| 반복 주기(`repeat_rule`) | O | `daily` · `weekdays` · `weekly:1,3,5` |
| 종료일(`ended_at`) | ✗ | 없으면 무기한 |
| 관련 지식(`knowledge_id`) | ✗ | 🔴 nullable |

⚠ 반복 주기를 복잡하게 만들지 않는다. "매월 셋째 화요일" 같은 것은 습관 앱의 영역이고
우리는 습관 앱이 **아니다**(기획서 §31).

### 2.1 🔴 `active` 는 스위치이지 만료 표시가 아니다 (2026-09-10)

| 무엇 | 어디서 나오나 |
|---|---|
| **그만두기** | `active = 0`. 사용자가 눌러야 바뀐다 |
| **종료됨** | `ended_at` 이 오늘보다 이전인가. **매번 판정한다** |
| **아직 시작 안 함** | `started_at` 이 오늘보다 이후인가. 매번 판정한다 |

🚫 종료일이 지났다고 `active` 를 0 으로 고쳐 두지 않는다. 그건 **저장된 파생값**이고
`DATABASE.md` §4 가 금지하는 그것이다. 무엇보다 그렇게 하려면 **누가 언제 고칠 것인가**를
정해야 하는데(앱을 켤 때? 자정에?), 앱을 한 달 안 켠 사용자에게는 아무도 안 고쳐 준다.

오늘의 실천 질의는 넷을 함께 본다.

```sql
WHERE deleted_at IS NULL AND active = 1
  AND started_at <= :today
  AND (ended_at IS NULL OR ended_at >= :today)
```

## 3. 오늘의 실천

```
오늘의 실천
┌─────────────────────────────────┐
│ 스마트폰을 자기 전에 책상에 놓기     │
│ 월  화  수  목  금  토  일          │
│ ●   ●   ●   ○   ○   ○   ○          │
│ 3일 연속 실천          기록 보기 › │
└─────────────────────────────────┘
```

- 🔄 **실천마다 카드 하나**다(2026-09-15 관리자 수정사항 #3 *"각 실천별로 영역 구분을 할 수 없어"*). 아래의 시작 전 · 지난 실천 카드와 같은 모양이다.
- 🔄 **아래 오른쪽 `기록 보기 ›`** 가 상세(한 달 기록 달력 · §3.1)로 간다(관리자 수정사항 #2 *"클릭할 수 있는지도 몰랐다"*). 제목도 여전히 눌린다.
  - 🔴 **카드 전체를 누르게 하지 않는다.** 요일 칸을 누르다 상세로 넘어가면 체크가 안 된다.
  - 🔴 링크 색은 **글자색**(`label 13/18 600`)이다. ChatGPT 는 accent 를 권했지만 오늘의 실천이 여럿이면 링크도 여럿이라 accent 가 화면에 여럿 생긴다(`DESIGN_REVIEW.md` §3).
  - `›` 는 글자다. 본문에 아이콘을 쓰지 않는 규칙(`UI_GUIDE.md` §2.1)을 지킨다.
  - 연속일이 0 이면 왼쪽은 비고 링크만 오른쪽에 남는다(§8).
- ✅ **에뮬레이터 확인(2026-09-15 · AVD `reread` 5574 · Expo Go · ko)**. 오늘의 실천 둘이 카드 둘로 나뉜다 · 오늘 칸을 누르면 **상세로 안 넘어가고** 체크되며 왼쪽에 `1일 연속 실천` 이 생긴다 · `기록 보기 ›` 와 제목이 둘 다 한 달 달력 상세를 연다.

- ~~홈에서~~ **실천 탭 위쪽에**, 실천이 있는 사용자에게만 보인다(기획서 §13 "실천을 생성한 사용자에게만 제공" · 🔄 2026-09-14 결정 #26 으로 홈에서 옮겼다).
  실천이 0개인 사용자에게 실천 영역을 빈 상태로 두지 않는다 — 안 만든 것이 정상이다(기둥 4).
- 체크는 1탭. `practice_logs`에 `(practice_id, date)` UNIQUE로 하루 1건.
- 🔴 **과거 날짜 체크를 허용한다.** 어제 했는데 오늘 켠 사용자가 실제로 많다.
  미래와 종료일 뒤만 막는다. 🔄 ~~시작일 이전도 막는다~~ → **시작일 이전도 체크한다**(2026-09-18 · §3.2).
- 체크 해제도 허용한다(잘못 눌렀을 때).

### 3.1 기록 달력: 지난 날도 체크한다 (2026-09-14)

사용자 *"실천을 하면 주간밖에 안 보이는데 이때까지 실천했던 기록은 어떻게 되는거야? 캘린더로도 보여주면 좋을 것 같은데"*.
기록은 처음부터 `practice_logs` 에 날짜별로 남아 있었다. **보여주는 화면이 이번 주 일곱 칸뿐**이었다.

```
‹        2026년 9월        ›
월  화  수  목  금  토  일
    1   2   3   4   5   6
7   ●   ●   10  ●   12  13
(14) 15  16 …
```

- 실천 **상세**의 이번 주 칸을 한 달 달력으로 바꿨다. 실천 **탭**의 오늘 칸(일곱 칸)은 그대로다.
- ‹ › 로 달을 넘긴다. 🔴 **이번 달보다 뒤로는 안 간다**(종료된 실천은 종료한 달까지 · 시작 전 실천은 시작하는 달까지). 🔄 앞쪽은 §3.2 의 범위까지 간다(~~시작한 달보다 앞으로 안 간다~~).
- 🔴 **지난 날도 누르면 체크된다**(사용자 선택). 규칙은 §3 과 같은 `canCheck` 하나다. 미래 · 종료 뒤는 흐리게 두고 안 눌린다(🔄 2026-09-18 시작일 이전은 눌린다 · §3.2).
  달력에 규칙을 따로 두면 주 칸과 달력이 같은 날을 다르게 판정한다.
- 🚫 달 성공률 · 채운 칸 수 · 빈칸 강조가 없다(§4). 한 날은 채운 동그라미, 안 한 날은 그냥 숫자다. 오늘은 테두리다.
- 주는 월요일에 시작한다(§3 의 `월 화 수 …` 와 같다). 달 이름은 기기 로케일이다.
- 계산은 `monthCells` · `calendarBounds`(`features/practice/compute.ts`)와 `addMonths` · `daysOfMonth`(`lib/day.ts`)이고 가드 ⑨ 가 잰다.

### 3.2 시작일 이전도 체크한다 (2026-09-18)

사용자 지시 *"실천 캘린더 등록한 날짜부터 오늘까지로 나오는데 이미 실천하고 있는데 이 앱을 뒤늦게 접해서 진행하는 경우도 있을 것 같아 과거부터 오늘까지로 해제해줄래"*.
실천을 만든 날이 곧 시작일이다(만들기 화면에 시작일을 고르는 칸이 없다). 그래서 **이미 하던 실천을 뒤늦게 등록한 사람은 등록 전 기록을 남길 자리가 없었다.**

- 🔴 **체크를 막는 것은 미래와 종료일 뒤 둘뿐이다.** 시작일은 체크를 막지 않는다(`canCheck`).
- 시작일의 뜻은 **오늘의 실천에 나타나기 시작하는 날**로 남는다(`isRunning` · §2.1). 기록의 하한이 아니다.
- 🔴 **연속일은 시작일 이전 기록도 이어서 센다**(§6.1 4번). 등록 전부터 매일 해 온 사람이 등록한 날 `1일 연속` 을 보면 사실이 아니다.
- 달력은 앞쪽으로 **이번 달 포함 12개월**까지 간다. 그보다 이른 시작일이나 기록이 있으면 그 달까지 간다(`calendarBounds`). 뒤쪽 한계는 §3.1 그대로다.
- 시작 전 실천(시작일이 미래)도 지난 날은 체크된다. 이미 하던 것을 다음 주 시작으로 등록한 경우다.
- 🚫 시작일을 과거로 고르는 입력 칸은 만들지 않았다. 체크를 푸는 것으로 끝나는 일에 입력 칸을 늘리지 않는다.

대가: ① 기록이 없는 빈 달을 최대 11번 넘길 수 있다. §3.1 의 *"빈 달을 넘기게 하지 않는다"* 를 이 범위에서 푼다. ② 1년보다 앞선 날은 그때 기록이 있어야만 달력이 거기까지 간다.
- 계산은 `canCheck` · `practiceStreak` · `calendarBounds`(`features/practice/compute.ts`)이고 가드 ④ · ⑨ 가 잰다.

## 4. 🚫 하지 않는 것

기둥 5(시험 앱이 아니다)가 실천에도 그대로 적용된다.

| 안 하는 것 | 왜 |
|---|---|
| 실천 성공률을 성적으로 보여주기 | 실천은 평가 대상이 아니다. 2차에서도 **회고 재료**로만 |
| 연속일이 끊길까 봐 압박하는 알림 | "3일 연속이 오늘 끊깁니다" 류 금지 |
| 미달성 실천을 붉은색·경고로 표시 | 못 한 날은 그냥 빈 동그라미다 |
| 실천 생성을 유도하는 반복 배너 | [넘어가기]는 영구적이다(§1) |
| 실천 수를 KPI로 두는 화면 설계 | 기둥 4 |

## 5. 지식과의 관계 — 분리한다

```
knowledge (1) ──── (0..N) practices
                       🔴 nullable 연결
```

기획서 §29가 명시적으로 요구한 분리다.

| 지우는 것 | 실천은 |
|---|---|
| 지식 삭제 | **남는다.** `knowledge_id`를 NULL로 끊는다 — 실천은 이미 사용자의 생활이지 지식의 부속이 아니다 |
| 실천 삭제 | 지식은 그대로. `practice_logs`는 tombstone |
| 책 삭제 | 아무 영향 없음 |

⚠ 연결이 끊긴 실천의 화면에는 "관련 지식 없음"이 아니라 **아무것도 표시하지 않는다.**
없는 것을 결핍으로 보여주지 않는다.

## 6. 연속일 — 두 축을 섞지 않는다

| 무엇 | 어떻게 센다 | 어디에 보인다 |
|---|---|---|
| **학습 연속일** | 복습 또는 저장 활동이 있는 날 | 홈 · 통계 |
| **실천 연속일** | 해당 실천의 `practice_logs` | 그 실천 카드 |

🔴 **하나로 합치지 않는다.** 실천이 없는 사용자도 학습 연속일을 가져야 하고(기둥 4),
실천 연속일은 실천마다 따로다.

- 둘 다 **파생값**이다. 저장하지 않고 매번 센다.
- `repeat_rule`이 `weekdays`인 실천은 **주말을 끊김으로 세지 않는다.** 이걸 틀리면
  성실한 사용자에게 "끊겼다"고 말하게 된다.

### 6.1 실천 연속일 — 정확히 어떻게 세나 (2026-09-10)

```
1. 오늘 체크했으면 오늘부터, 아니면 어제부터 거슬러 센다
2. 거슬러 가다 **그 실천의 예정일이 아닌 날**은 건너뛴다(끊김도 아니고 세지도 않는다)
3. 예정일인데 기록이 없으면 거기서 멈춘다
4. 가장 이른 기록보다 앞으로는 안 간다(🔄 2026-09-18 ~~시작일 이전으로는 안 간다~~ · 시작일 이전 기록도 센다 · §3.2)
```

🔴 **2번이 `weekdays` 실천의 급소다.** 금요일까지 한 사람이 월요일 아침에 열었을 때
토·일을 끊김으로 세면 `0일` 이 된다. 사실이 아니고, 기둥 5 와도 부딪힌다.

🔴 **1번은 학습 연속일과 같은 규칙이다**(`STATS_SYSTEM.md` §3.3).
*"하루가 끝나기 전에는 그 하루를 실패로 세지 않는다."* 두 곳에서 규칙이 다르면
사용자는 같은 화면에서 서로 다른 셈법을 보게 된다.

⚠ 예정일이 아닌 날에 체크한 기록(§7 의 `weekly:1,3,5` 를 화요일에)은 **버리지 않는다.**
연속을 이어 주지도, 끊지도 않는다. 규칙은 계산용이지 잠금이 아니다.

- 🚫 실천 탭의 오늘 영역은 **진행 중인 실천이 0개면 그리지 않는다**(§3). 빈 상자를 만들지 않는다.
- 🔴 **누를 수 없는 칸(미래 · 종료 뒤)은 흐리게, 오늘 요일은 굵게** 그린다(2026-09-14 · 🔄 2026-09-18 시작 전은 뺐다 · §3.2). 판정(`checkable`)은 처음부터 있었는데
  모양이 따라오지 않아 **모든 요일이 눌리는 것처럼 보였다**(사용자 지적 *"실제로 해당 요일만 클릭 가능한 거 같은데 맞아?"*). 색은 쓰지 않는다(기둥 5).

- 🚫 연속일이 0 이면 `0일 연속` 이라고 쓰지 않고 **그 줄을 안 그린다**
  (`STATS_SYSTEM.md` §4.1 과 같은 규칙).
- 미래 날짜 칸은 **누를 수 없다.** 🔄 시작일 이전 칸은 누를 수 있다(2026-09-18 · §3.2).

## 9. 가드 — `npm run check:practice`

| 축 | 무엇을 잰다 |
|---|---|
| ① 반복 규칙 | `daily` · `weekdays` · `weekly:1,3,5` 가 맞는 요일에만 예정되나 · 깨진 문자열을 삼키지 않나 |
| 🔴 ② weekdays 주말 | 금요일까지 이어온 실천이 **월요일에 끊겨 있지 않나** |
| ③ 연속일 경계 | 오늘 아직 안 했을 때 **어제까지의 연속이 유지되나** |
| ④ 시작일 이전 기록 | 🔄 2026-09-18 시작일 이전 날을 체크할 수 있나(주 칸 · 달력 · `canCheck`) · 그 기록이 연속일에 이어지나 · 종료일 뒤는 여전히 막나(~~시작일 이전으로 거슬러 세지 않나~~). ⚠ 연속일의 "가장 이른 기록에서 멈춘다"는 결과를 안 바꾸는 반복 상한이라 가드로 못 잰다 |
| ⑤ 오늘의 실천 질의 | `active` · `started_at` · `ended_at` · tombstone 넷을 다 보나 |
| ⑥ 하루 1건 | 같은 날 두 번 체크해도 1건인가 · 해제 후 재체크가 되나(tombstone 되살리기) |
| ⑦ 지식 삭제 | 지식을 지워도 실천이 살아 있고 `knowledge_id` 만 끊기나 |
| 🔴 ⑧ 넘어가기 | [넘어가기] 뒤에 **제안이 다시 안 뜨나**(v5 컬럼) |
| 🔴 ⑨ 기록 달력 | 1일이 **그 요일 칸**에 서나(화 · 일 · 월 시작 달 · 평년/윤년 2월) · 칸 수가 7 의 배수인가 · 누를 수 있는 날이 `canCheck` 와 같은가 · 달 넘기기가 앞쪽 12개월(더 이른 시작일 · 기록이 있으면 그 달)까지 가고 마지막 달 밖으로 안 나가나(종료 · 시작 전) · 깨진 달 키를 조용히 받지 않나 · 상세 화면이 달력을 그리나 |
| SELF-TEST | 판정 함수가 살아 있는지 **먼저** 증명한다(exit 2) |

## 7. 엣지 케이스 (v1 착수 시 `EDGE_CASES.md`로 이관)

| 상황 | 기대 동작 |
|---|---|
| `actionability='high'`인데 [넘어가기] | 영구 기록. 다시 묻지 않는다 |
| 지식 없이 실천만 만들기 | 허용(`knowledge_id` NULL). 실천 탭의 [실천 만들기](🔄 2026-09-14 · 홈 아래 링크에서 옮김) |
| 종료일이 지난 실천 | 오늘의 실천에서 빠지고 목록에서 `종료됨` 으로 접힌다. 기록은 남는다.
  🔴 `active` 를 고치지 않는다(§2.1) |
| 같은 날 두 번 체크 | UNIQUE로 1건. 두 번째는 무시(오류 아님) |
| 시간대 이동 중 체크 | `date`는 **로컬 날짜**로 기록. 하루가 겹치거나 비어도 그대로 둔다 |
| `weekly:1,3,5` 실천을 화요일에 체크 | 허용. 규칙은 알림·연속일 계산용이지 잠금이 아니다 |
| Premium 해지 | 🔴 기존 실천과 체크는 **계속 동작한다.** 새 실천 생성만 막힌다 |
