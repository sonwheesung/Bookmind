## 1. 결정은 코드보다 먼저 문서에

> 표준 작업 순서 정본은 [`../CLAUDE.md`](../CLAUDE.md) §13 — ① 플랜 → ② **문서(코드보다 先)** → ③ 개발 → ④ 검증 → ⑤ 커밋.

- 새 설계 결정은 **코드보다 먼저** 문서에 반영한다 — 루트 `CLAUDE.md`(기둥·결정 로그) 또는
  `docs/<SYS>_SYSTEM.md`(시스템 상세) + `docs/README.md` 색인.
- "왜 이렇게 정했나"와 **"무엇을 포기했나"** 를 함께 적는다.
  > 예: 로컬 정본 = 웹 계획 없음 + 서버 마이그레이션 비용 회피(2026-09-08). **대가: 기기 교체 시 전손.**
  > 예: 회상 질문 저장 시 1회 생성 = 비용 + 오프라인(2026-09-08). **대가: 질문이 고정된다.**
- 🔴 **기획서를 뒤집은 결정은 반드시 `CLAUDE.md` §14에 근거와 함께 적는다.**
  기획서([`ORIGINAL_BRIEF.md`](./ORIGINAL_BRIEF.md))는 역사 문서이고 정본이 아니다.

## 2. 시스템마다 `*_SYSTEM.md`

- 각 독립 시스템은 자기 설계 문서를 가진다(단일 책임 = 단일 문서).
- 🔴 **문서 상단에 "0. 구현 현황" 표를 둔다**(✅/🔨/❌/⏸/🚫). 설계만 적고 현황을 안 적으면
  "문서에 있으니 됐겠지"가 된다. **일관성 검증은 이 표를 기준으로 한다.**

## 3. README 색인 (docs/README.md)

색인이자 **구현 현황의 정본**이다. 다른 세션이 이 파일만 읽고도 전체를 돌릴 수 있어야 한다.
새 `*_SYSTEM.md`를 만들면 **반드시** 색인 목록과 구현 현황표에 함께 등록한다(부록 체크리스트).

## 4. 🔴 손으로 적은 수 옆에 세는 법을 함께 적는다

이 계보가 가장 비싸게 배운 규칙이다. **개수는 반드시 늙는다.**

```
| 확정 결정 **12건**(세는 법: `grep -c "^\*\*#" CLAUDE.md`) |
```

세는 법이 있으면 값이 늙어도 **늙었다는 걸 검출할 수 있다.** 없으면 그 수는 조용히 거짓이 된다.

⚠ 그런데 **세는 법은 검출 가능하게 할 뿐 검출하지는 않는다**(농구명가 2026-08-30: 규칙을 다 지켰는데
아무도 명령을 안 돌려서 처음 대조한 날 세 곳이 이미 틀려 있었다). 파생값을 직접 세어 대조하는
스크립트를 만들면 [`README.md`](./README.md) §3 검증 루틴에 **명령을 추가하는 것까지가 완료**다.

🚫 **실측치는 자동 대조 대상이 아니다** — 응답 시간·AI 원가처럼 *다시 재야 아는 값*을 대조하면
거짓 확신이 된다. 대상은 **세면 나오는 수**뿐이다.

## 5. 날짜는 절대값 · 정정은 취소선

- `(2026-09-08 결정)` — "최근"·"얼마 전" 금지.
- 🔴 **뒤집힌 결정은 지우지 않는다.** ~~취소선~~ + 무엇이 뒤집었는지 + 날짜.
  지우면 "왜 안 그랬는지"를 다음 세션이 또 논의한다.

## 6. 케이스(무엇)와 방법(어떻게)을 섞지 않는다

| | 어디 | 무엇 |
|---|---|---|
| **케이스** | `docs/EDGE_CASES.md` | 어떤 버그가 있었나 · 무엇을 검사하나 — 증상 → 원인 → 수정 → 가드 |

버그를 고치면 **"왜 기존 검증이 못 잡았나"(사각 분석) + 사각을 닫는 케이스 추가**까지가 완료다.

## 7. 도메인·라이브러리 사실은 출처로 (추정 금지)

- SDK/스토어 정책/법령은 구현 전 **공식 문서로 확인**한다. 기억으로 단정 금지.
- 🔴 값을 "미확인"으로 적기 전에 **형제 레포와 `common/`을 먼저 grep한다.**
  이미 확정된 값을 다시 물어보는 낭비가 실제로 발생했다.
  `grep -rl "<개념>" C:/project/*/docs/` · `C:\project\common\BUSINESS_INFO.md`
