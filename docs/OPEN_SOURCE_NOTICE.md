## 1. 🔴 왜 손으로 적지 않는가

MIT·ISC·BSD·Apache 는 *"저작권 고지와 허가 고지를 사본에 포함하라"* 를 요구한다. 그래서 **배포하는 것**에
고지 의무가 걸린다(`devDependencies` 는 안 실리므로 빠진다).

🔴 **손으로 적은 목록은 다음 `npm i` 에 늙는다. 그리고 고지의 거짓은 라이선스 위반이다.**

형제 여섯이 전부 이 항목을 **출시 직전에** 발견했다(배구 · 조각 · LinkMemo · My Word · 농구 · Idea Repository).
그 가운데 한 건은 더 나빴다.

> **My Word 는 2026-09-02 에 176개로 고쳤는데, 09-07 에 다시 176개인 채로 올릴 뻔했다.**
> `expo-notifications` 를 넣고 생성기를 안 돌린 것이다. 재생성하니 **215개**(39개 누락).
> 🔴 **생성기만 있고 가드가 없으면 그 생성물은 반드시 낡는다.**

→ 그래서 우리는 ② 와 ③ 을 **같은 날 같이** 만들었다. 둘 중 하나만 있는 상태로 커밋하지 않는다.

## 2. 🔴 가드가 생성기의 선정 규칙을 베끼지 않는다

`check:licenses` 는 **생성기를 다시 돌려 그 출력과 커밋된 파일을 바이트로 비교**한다. 규칙을 두 번 쓰지 않는다.

> ⚠ My Word 는 가드가 선정 규칙(`npm ls --omit=dev`)을 **베끼도록** 짰다가 버렸다.
> 생성기는 `node_modules` 에 실제로 설치된 것만 세는데 베낀 쪽은 이름만 봐서 **604 vs 215** 오경보가 났다.
> 🔴 **틀린 가드는 없는 것보다 나쁘다** — 오경보가 나면 사람이 꺼 버리고, 꺼진 가드는 다음 사람에게
> *"원래 시끄러운 것"* 으로 전수된다.

성립 조건 둘: 생성 출력이 **정렬돼 있고**(패키지 이름순 · 라이선스 종류 키도 정렬), **타임스탬프가 없다.**

⚠ **줄끝을 맞춰서 비교한다.** `core.autocrlf=true` 인 윈도는 체크아웃이 LF 를 CRLF 로 바꾼다. 그대로 비교하면
**새로 클론한 사람에게서만** FAIL 한다(형제가 커밋 직후 재현했다). 그래서 비교 전에 CRLF 를 LF 로 접는다.

⚠ **`features/legal/credits.json` 은 `.prettierignore` 에 있다.** 한 줄 JSON 인데 prettier 가 다시 포매팅하면
바이트 비교가 거짓 실패를 낸다.

## 3. 🔴 전이 의존까지 따라간다

`dependencies` 에서 시작해 각 패키지의 `dependencies` 를 **전이로** 따라가고, `node_modules` 를
**부모 디렉터리에서부터 위로** 찾는다(npm 호이스팅 그대로).

> ⚠ 농구명가는 루트에서만 찾다가 **호이스팅 안 된 중첩 의존 161개를 놓쳤다**(446 → 607).

🟢 **과대 포함은 안전한 방향이다.** 트리 기준이라 실제 번들에 안 들어가는 CLI 도구도 섞인다
(우리 657개에 `lightningcss` 처럼 웹 도구가 섞여 있다). 빠뜨리는 것이 위반이고 더 적는 것은 위반이 아니다.

### 담는 모양

| | 왜 |
|---|---|
| `packages[]` = `{n: 이름, v: 버전, l: 라이선스, c?: 저작권 줄}` | 저작권 줄은 패키지마다 다르다 |
| `licenses[종류]` = 허가 고지 본문 **1벌** | 🔴 MIT 사본 수백 개는 **저작권 줄만 다르고 허가 고지는 같은 글**이다. 전문을 수백 벌 담으면 400KB+ 인데 종류로 묶으면 **174KB** 다 |

- 🚫 **저작권 줄이 없으면 비운다.** 657개 중 **85개**가 `LICENSE` 파일에 저작권 줄을 안 싣는다.
  **없는 고지를 지어내지 않는다.** 화면이 그 사실을 한 줄로 알린다.
- 🚫 **번역하지 않는다.** 라이선스 본문·저작권자·라이선스명은 원문 그대로다.
- ⚠ 라이선스 표기가 네 모양으로 온다(`license` 문자열 · `license.type` · `licenses[]` 옛 형식 ·
  `license: "None"` 인데 `licenses` 에 실제 값). 못 읽으면 화면에 `UNKNOWN` 이 뜬다 → 네 모양을 다 본다.
  🟢 우리 실측 `UNKNOWN` **0개** · 본문 없는 종류 **0개**.

## 4. 🔴 카피레프트 판정 — 이름만 보면 틀린다

`npm run licenses:build` 를 처음 돌린 날 가드가 즉시 멈췄다.

```
🔴 카피레프트 1개: node-forge((BSD-3-Clause OR GPL-2.0))
```

**거짓 경보였다.** `node-forge` 는 이중 라이선스고 **우리가 BSD-3-Clause 를 고르면 된다.**
문자열에 `GPL` 이 있다는 이유로 멈춘 것이다.

→ SPDX 식을 읽게 고쳤다(`needsCopyleft`).

| 연산자 | 판정 | 왜 |
|---|---|---|
| `OR` | **전부** 카피레프트일 때만 의무가 생긴다 | 고를 수 있다 |
| `AND` | **하나라도** 카피레프트면 의무가 생긴다 | 전부 적용된다 |
| `WITH` | 보수적으로 카피레프트로 본다 | 예외 조항을 해석하지 않는다 |

★ **§2 의 교훈과 같은 자리다.** 가드가 틀리면 사람이 끈다. 그래서 자체 검사에 **양성 대조와 음성 대조를
둘 다** 뒀다(`GPL-3.0`·`LGPL-2.1`·`CC-BY-SA` 는 잡혀야 하고, `MIT`·`Apache-2.0`·`CC0`·`0BSD` 는 안 잡혀야 한다).

### 🟡 약한 카피레프트 1개 — `lightningcss` (MPL-2.0)

MPL-2.0 은 **그 파일을 고쳤을 때** 그 파일의 소스를 공개하라고 한다(파일 단위 · 약한 카피레프트).

- 🟢 **우리는 의존을 고치지 않고 그대로 싣는다.** 그래서 지켜야 할 것은 ① 라이선스 본문 고지(생성기가 담는다)
  ② 소스 입수 경로다. ②는 npm 레지스트리의 그 패키지 페이지이고, **화면이 그 경로를 한 줄로 알린다.**
- 🔴 **의존을 포크해서 고치는 날 이 줄의 뜻이 바뀐다.** 그래서 생성기는 매 실행마다 이 목록을 출력한다
  (조용히 지나가지 않는다). `check:licenses` 의 끝줄에도 개수가 나온다.

⚠ 657개를 줄마다 `View` 로 그리면 요소가 2천 개가 된다. 그래서 **60개씩 묶어 `Text` 한 덩이**로 그린다.
