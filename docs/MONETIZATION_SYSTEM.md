## A. 🔴 광고 · 광고 제거 구현 (2026-09-21 · 결정 #29 · #31)

사용자 *"전부 다 진행해줘"*. 원본은 My Word(`C:\project\my_word\My_word`)의 `src/components/AdBanner.tsx` ·
`src/hooks/useInterstitialAd.ts` · `src/contexts/PurchaseContext.tsx` 이고, 같은 Expo SDK 54 · RN 0.81.5 라 그대로 옮긴다.
구조만 우리 방식(zustand 저장소 · 순수 판정은 `compute` 파일 · 가드)으로 바꾼다.

### A.1 부팅 흐름

```
부팅 → 연령 확인(결정 #25)이 끝나기를 기다린다(통과 · 미달 · 닫음 모두 끝이다)
     → 맞춤 광고 판정  decideAdRequest(통과 기록 · 미달 기록)          ← 순수 · 가드가 잰다
     → 광고 동의 UMP   requestInfoUpdate → 필요하면 폼(EEA · 영국)     ← 미달이면 미성년 표시로 폼을 안 띄운다
     → setRequestConfiguration → initialize → ready
     → 배너 · 전면은 ready 뒤에만 광고를 요청한다
광고 제거: 부팅 때 캐시를 먼저 읽고 → Play 에 다시 묻고(getAvailablePurchases) → 캐시를 갱신한다
```

- 🔴 **연령 확인보다 먼저 광고를 요청하지 않는다.** 미달인 사람에게 맞춤 광고가 한 번이라도 나가면 되돌릴 수 없다.
- 🔴 **광고 제거를 산 사람은 SDK 초기화도, 광고 요청도 하지 않는다**(My Word 규칙 · 보이지 않을 광고를 부르지 않는다).
- 광고 모듈이 없는 환경(Expo Go)에서는 조용히 아무것도 안 한다. 앱은 그대로 돈다.

### A.2 맞춤 광고 판정 (`features/ads/compute.ts`)

| 연령 기록 | 맞춤 광고 | 미성년 표시(`tagForUnderAgeOfConsent`) |
|---|---|---|
| 통과(유효) | 허용(동의가 있을 때) | 아니오 |
| 미달(유예 안) | 🔴 끈다 | 예 |
| 없음(닫았음 · 못 읽음) | 🔴 끈다 | 아니오 |

🔴 **모르면 끈다.** 통과 기록이 있을 때만 맞춤 광고가 열린다. 비맞춤 광고는 광고 수익이 줄지만 틀릴 수 없는 쪽이다.

### A.3 배치 (`features/ads/compute.ts` 의 `AD_PLACEMENTS` · 가드가 화면 파일과 대조)

| 종류 | 화면 | 조건 |
|---|---|---|
| 하단 고정 배너(적응형) | 홈 `app/(tabs)/index.tsx` · 문장 `app/(tabs)/knowledge.tsx` · 책 `app/(tabs)/books.tsx` · 복습 끝 `app/review.tsx` | `Screen` 의 `footer` 자리(스크롤 밖) · 탭 화면에서는 탭 바 바로 위 |
| 전면 | 복습 끝 `app/review.tsx` | 끝 화면에 들어온 뒤 **500ms** · **한 번** · 🔴 이번 복습에서 **한 장 이상 넘겼을 때만**(빈 큐로 들어와 본 끝 화면은 복습을 마친 게 아니다) |
| 🚫 없음 | 문장 저장 · 수정 · 복습 진행 중 · 설정 · 백업 · 연령 확인 · 그 밖의 모든 화면 | 가드가 이 파일들에 광고 부품이 없는지 잰다 |

🚫 복습 **시작 전** 전면은 없다(결정 #31 · 기둥 7).

### A.4 광고 단위 ID (`features/ads/config.ts`)

- 개발 빌드(`__DEV__`)는 늘 Google 테스트 ID 를 쓴다.
- ✅ **2026-09-21 AdMob 에 Re:Read 앱과 광고 단위 둘을 만들었다**(§A.6.1 의 ID). ~~만들기 전에는 릴리스도 테스트 ID 다~~. 비공개 테스트 동안은 스위치가 꺼져 있어 어느 ID 로도 요청하지 않는다.
- `app.json` 의 `androidAppId` 도 같은 쌍이어야 한다. 🔴 가드가 **앱 ID 와 단위 ID 가 둘 다 테스트이거나 둘 다 실제**인지 잰다. 섞이면 광고가 안 나오거나 무효 트래픽이 된다.
- 실제 ID 를 받으면 `config.ts` 와 `app.json` 두 곳을 한 커밋에 바꾼다.

### A.5 광고 제거 (`features/purchase/`)

- 상품: 비소비성 `remove_ads` · `expo-iap` 로 Play 결제 직접. 🚫 서버 · RevenueCat · 영수증 서버 검증 없음(일회성이라 뚫려도 손해가 상품 한 건이다 · My Word 판단 승계).
- 🔴 **진실은 Play 다.** 기기 캐시(AsyncStorage `reread-ad-free`)는 부팅 직후 광고가 번쩍이지 않게 하는 용도다. 매 부팅 다시 확인하고, 환불되면 목록에서 빠지므로 다음 부팅에 광고가 돌아온다.
- 🔴 **Play 조회가 실패하면 캐시를 그대로 둔다.** 오프라인에서 산 사람에게 광고를 되돌려주지 않는다.
- 🔴 **`finishTransaction({ isConsumable: false })` 를 반드시 부른다.** 안 부르면 Play 가 3일 뒤 자동 환불한다.
- 결제 대기(`pending`)는 아직 지급하지 않는다. 판정은 순수 함수 `ownsRemoveAds` 하나다(가드가 잰다).
- 캐시 키는 백업 파일에 안 들어간다(백업은 DB 만 옮긴다). 기기를 바꾸면 `구매 복원` 으로 되찾는다.

## 1. ~~🔴 왜 광고를 넣지 않는가 (결정 #10)~~ 🔄 뒤집힘 (결정 #29 · 2026-09-21)

> 아래 근거 가운데 2번(기둥 1 · 저장 흐름과 복습 세션)은 **버리지 않고 광고 자리를 고르는 조건**이 됐다 — 그 두 곳과 연령 확인 · 백업 도중에는 광고를 띄우지 않는다(⚠ 미결정 I).

1. 기획서에 광고가 없다 — **없는 것을 발명하지 않는다.**
2. 배너·전면광고는 기둥 1(독서를 방해하지 않는다)과 **정면 충돌**한다. 저장 흐름과 복습 세션은
   이 앱에서 광고를 띄울 수 없는 두 지점인데, 그게 앱 사용 시간의 대부분이다.
3. 형제 앱들은 광고+일회성 구매 조합이지만 그건 **체류형 앱**이다. Re:Read는 짧게 들어왔다
   짧게 나가는 앱이라 노출도 적고 방해는 크다.

## 4. 결제 경로

🔄 **2026-09-21 RevenueCat 과 서버 엔타이틀먼트를 버렸다**(결정 #31). 일회성 구매에는 쓸 자리가 없다.

```

                      │
                      ▼
            Play 가 구매를 들고 있다 (진실)
                      │
앱: 매 부팅 getAvailablePurchases() 로 다시 확인 → 로컬 캐시(UI)
```

- 🔴 **진실은 Play 의 구매 내역이다.** 서버도 RevenueCat 도 없다. 우리가 보관할 것이 없으니 잃을 것도 없다.

## 6. 구현 시 함정 (형제 실증 승계)

- 🔴 **릴리스 AAB를 로컬에서 구울 때 개발용 env가 번들에 문자열로 박힌다**(조각 실증).
  EAS는 깨끗한 컨테이너라 없는 문제인데 로컬은 `.env.local`을 읽는다. **올린 뒤에는 못 고친다.**
  → 릴리스 빌드 전 env 검사 스크립트를 만들고 [`README.md`](./README.md) §3 검증 루틴에 넣는다.
- RevenueCat SDK는 **네이티브 모듈**이라 Expo Go에서 안 된다. 이 단계부터 dev build.
- 🔴 **스토어 상품 등록과 결제 빌드가 서로를 전제한다** — `common/PRE_LAUNCH_CHECK.md` §3 실측:
  *"결제 코드·빌드·업로드가 먼저, 콘솔 상품 등록이 그다음"*. 즉 Phase 10(구독)은 Phase 11의
  Play 콘솔·서명 키를 일부 **앞당겨** 써야 한다. 순서를 모르고 들어가면 Phase 10에서 막힌다.
- 🔴 **약관 게시가 결제 빌드보다 먼저다**(같은 문서 §2): ① 약관 게시 → ② 처리방침에 인앱 결제 항목
  신설·재게시 → ③ **그다음** 결제 빌드를 심사에 올린다. 우리 Phase 순서(10 결제 → 11 법무)와 반대다.
