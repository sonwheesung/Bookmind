## 1. ~~🔴 왜 광고를 넣지 않는가 (결정 #10)~~ 🔄 뒤집힘 (결정 #29 · 2026-09-21)

> 아래 근거 가운데 2번(기둥 1 · 저장 흐름과 복습 세션)은 **버리지 않고 광고 자리를 고르는 조건**이 됐다 — 그 두 곳과 연령 확인 · 백업 도중에는 광고를 띄우지 않는다(⚠ 미결정 I).

1. 기획서에 광고가 없다 — **없는 것을 발명하지 않는다.**
2. 배너·전면광고는 기둥 1(독서를 방해하지 않는다)과 **정면 충돌**한다. 저장 흐름과 복습 세션은
   이 앱에서 광고를 띄울 수 없는 두 지점인데, 그게 앱 사용 시간의 대부분이다.
3. 형제 앱들은 광고+일회성 구매 조합이지만 그건 **체류형 앱**이다. Re:Read는 짧게 들어왔다
   짧게 나가는 앱이라 노출도 적고 방해는 크다.

⚠ 이 결정을 뒤집으려면 §14에 새 번호로 올리고 기둥 1과의 충돌을 어떻게 해소할지 함께 적는다.

## 4. 결제 · 엔타이틀먼트 경로

```
앱 → RevenueCat SDK → 스토어 결제
                          │
                          ▼
        RevenueCat → common_server /api/webhooks/revenuecat/reread
                          │
                          ▼
                    entitlements 갱신
                          │
앱 → common_server /api/v1/entitlements ◀─┘   (진실)
Re:Read 서버 → common_server /api/v1/entitlements  (AI 게이트)
```

- 🔴 **진실은 common_server 엔타이틀먼트다.** 앱의 로컬 캐시는 UI용이고, **AI 게이트는 서버가 판정한다**
  (`AI_SYSTEM.md` §5). 클라이언트 게이트만 두면 우회된다.
- 🔴 **만료는 이벤트로 오지 않는다.** common_server는 `active`를 저장하지 않고 읽을 때 계산한다 —
  만료 순간에 DB를 쓰는 주체가 없다. 유예 기간이 필요한 기능(백업 v1.1)은
  **만료 시각 스냅샷을 우리 서버에 저장하고 우리가 센다**(조각 승계).
- **복원(Restore)** 경로를 반드시 둔다. 기기 교체·재설치 시 필요하고 스토어 심사 항목이다.

## 6. 구현 시 함정 (형제 실증 승계)

- 🔴 **릴리스 AAB를 로컬에서 구울 때 개발용 env가 번들에 문자열로 박힌다**(조각 실증).

- 🔴 **스토어 상품 등록과 결제 빌드가 서로를 전제한다** — `common/PRE_LAUNCH_CHECK.md` §3 실측:
  *"결제 코드·빌드·업로드가 먼저, 콘솔 상품 등록이 그다음"*. 즉 Phase 10(구독)은 Phase 11의

- 샌드박스 결제·환불 테스트 절차는 `store-iap-setup` 스킬 참조.
