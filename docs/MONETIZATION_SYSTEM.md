## 1. 🔴 왜 광고를 넣지 않는가 (결정 #10)

1. 기획서에 광고가 없다 — **없는 것을 발명하지 않는다.**
2. 배너·전면광고는 기둥 1(독서를 방해하지 않는다)과 **정면 충돌**한다. 저장 흐름과 복습 세션은
   이 앱에서 광고를 띄울 수 없는 두 지점인데, 그게 앱 사용 시간의 대부분이다.
3. 형제 앱들은 광고+일회성 구매 조합이지만 그건 **체류형 앱**이다. Re:Read는 짧게 들어왔다
   짧게 나가는 앱이라 노출도 적고 방해는 크다.

⚠ 이 결정을 뒤집으려면 §14에 새 번호로 올리고 기둥 1과의 충돌을 어떻게 해소할지 함께 적는다.

### 2.1 🔴 무료에서도 저장과 복습이 성립해야 한다 (결정 #9)

- 복습이 Premium 전용이 되면 **기둥 7이 깨진다** — 그럼 이 앱은 그냥 메모장이다.
- "책을 저장하려고 돈을 내는 게 아니다"(기획서 §28)가 정책의 기준선이다.
- → 무료 한도(⚠ A)는 **체험판이 되지 않을 만큼** 넉넉해야 한다. 너무 낮으면 위 문장이 거짓이 된다.
  ⚠ 미결정 A를 정할 때 이 문장을 기준으로 판단한다.

### 2.2 🔴 한도에 걸렸을 때의 동작

- **이미 저장한 것은 절대 잠그지 않는다.** 한도는 **새로 만드는 것**에만 적용된다.
- 무료로 내려온(해지한) 사용자의 기존 데이터는 전부 그대로 보이고 복습된다.
  🚫 "무료 한도 초과 — 12개가 잠겼습니다" 같은 인질 모델을 쓰지 않는다.
- 한도 안내는 저장 **직전**에 뜬다. 다 쓰고 나서 저장이 실패하는 흐름은 만들지 않는다.

### 2.3 해지 후

| | 해지 후 |
|---|---|
| 기존 AI 분석·회상 질문 | ✅ **로컬에 있으므로 계속 쓴다** |
| 기존 실천·체크 | ✅ 계속 동작 |
| 새 AI 분석 | ❌ |
| 새 실천 생성 | ❌ |
| 새 책·지식 | 무료 한도 적용 |
| 백업(v1.1) | 복원은 ✅ · 새 백업 ❌ + 유예 90일(조각 승계) |

🔴 이게 로컬 정본의 장점이다 — **산 것은 남는다.** 서버 정본이면 해지 시 접근을 끊게 되는데,
그건 사용자가 몇 년치 지식을 인질로 잡히는 구조다.

## 4. 결제 · 엔타이틀먼트 경로

```
앱 → RevenueCat SDK → 스토어 결제
                          │
                          ▼
        RevenueCat → common_server /api/webhooks/revenuecat/reread
                          │
                          ▼
                    entitlements 갱신
                          │
앱 → common_server /api/v1/entitlements ◀─┘   (진실)
Re:Read 서버 → common_server /api/v1/entitlements  (AI 게이트)
```

- 🔴 **진실은 common_server 엔타이틀먼트다.** 앱의 로컬 캐시는 UI용이고, **AI 게이트는 서버가 판정한다**
  (`AI_SYSTEM.md` §5). 클라이언트 게이트만 두면 우회된다.
- 🔴 **만료는 이벤트로 오지 않는다.** common_server는 `active`를 저장하지 않고 읽을 때 계산한다 —
  만료 순간에 DB를 쓰는 주체가 없다. 유예 기간이 필요한 기능(백업 v1.1)은
  **만료 시각 스냅샷을 우리 서버에 저장하고 우리가 센다**(조각 승계).
- **복원(Restore)** 경로를 반드시 둔다. 기기 교체·재설치 시 필요하고 스토어 심사 항목이다.

## 5. 법적 의무 세트

🔴 **글로벌 출시이므로 한국 기준만으로 부족하다.** 정본은 `C:\project\common\GLOBAL_DATA_COMPLIANCE.md`.

| 항목 | 필요한 것 |
|---|---|
| 자동갱신 고지 | 갱신 주기·금액·해지 방법을 **구매 화면에** 명시 |
| 해지 경로 | 앱 안에서 스토어 구독 관리로 가는 링크 |
| 환불 | 스토어 정책 안내 + 문의 경로 |
| 미성년자 결제 | 연령 게이트(⚠ 미결정 G)와 연결 |
| 가격 표시 | 국가별 현지 통화 · 세금 포함 여부 |
| EEA | GDPR 고지 · 구독 철회권(Digital Content Directive) |
| 미국 | 주법별 고지(CCPA/CPRA 등) |
| 한국 | 전자상거래법 표준약관 · 청약철회 |
| **탈퇴** | 🔴 **앱 내 경로 + 웹 URL 둘 다.** 하나만 있으면 반려된다(`GLOBAL_DATA_COMPLIANCE.md` §6.1) |
| 🔴 **계정 삭제 ≠ 구독 해지** | 탈퇴 화면에 **별도 해지 안내**. 계정만 지우고 구독이 살아 있으면 **과금이 계속된다** — 그게 분쟁이 된다 |
| Play 데이터 보안 | ⚠ **RevenueCat SDK 가 보내는 것도 "공유"로 선언**한다. *"우리 코드가 안 보낸다"* 는 근거가 안 된다(같은 문서 §6) |
| 웹에 있어야 하는 것 | 처리방침 · 이용약관 · **계정 삭제 안내 URL** — 셋 다 Play 콘솔 등록 + **200 응답 실측**(같은 문서 §8) |

⚠ 법률 문서(처리방침·약관)는 Phase 8에서 `LEGAL_SYSTEM.md`로 분리한다.
🔴 **AI 고지가 처리방침에 들어간다** — "원문이 AI 제공자에게 전달되며 저장되지 않는다"
(`AI_SYSTEM.md` §2.1). 이건 게시 **전에** 확정돼야 한다.

## 6. 구현 시 함정 (형제 실증 승계)

- 🔴 **릴리스 AAB를 로컬에서 구울 때 개발용 env가 번들에 문자열로 박힌다**(조각 실증).
  EAS는 깨끗한 컨테이너라 없는 문제인데 로컬은 `.env.local`을 읽는다. **올린 뒤에는 못 고친다.**
  → 릴리스 빌드 전 env 검사 스크립트를 만들고 [`README.md`](./README.md) §3 검증 루틴에 넣는다.
- RevenueCat SDK는 **네이티브 모듈**이라 Expo Go에서 안 된다. 이 단계부터 dev build.
- 스토어 상품은 **심사 전에 등록**돼야 테스트할 수 있다. Phase 7을 늦게 잡으면 출시가 밀린다.
- 샌드박스 결제·환불 테스트 절차는 `store-iap-setup` 스킬 참조.
