## 1. 🔴 왜 첫날에 세우는가

나중에 붙이면 **하드코딩된 문자열을 전부 찾아내는 작업**이 된다. 그리고 그건 반드시
몇 개를 놓치고, 놓친 것은 **다른 언어 사용자에게만 보이므로 우리가 모른다.**

첫날에 세우는 것은 언어 파일 2개가 아니라 **규약과 가드**다.
언어 추가가 **파일 추가만으로** 되는 상태를 만들어 둔다.

## 2. 언어

| 단계 | 언어 |
|---|---|
| **MVP** | `en`(기본) · `ko` |
| 확장 후보 | 조각의 15개 세트 — `de es fr id it ja pt-BR ru th tr vi zh-Hans zh-Hant` |

- 기본값은 **기기 언어**를 따르고, 지원하지 않는 언어면 `en`으로 떨어진다.
- 설정에서 수동 선택 가능. 🚫 "시스템 자동" 항목은 두지 않는다
  (Idea Repository가 2026-08-27에 제거했다 — 상태가 셋이 되면 마이그레이션과 버그가 는다).

### 2.1 🔴 언어 설정 화면을 Phase 6 → Phase 2 로 당겼다 (2026-09-09)

**이유는 기능이 아니라 검증이다.** 화면이 늘어나는 동안 `en`/`ko` 를 대조하려면 매번
기기 설정을 바꿔야 했고(§0.1 의 `adb setprop` + zygote 재시작), 그건 **두 언어 중 하나를
안 보게 되는 지름길**이다. 안 보는 언어는 반드시 깨진다 — 그리고 그 깨짐은 **그 언어를 쓰는
사용자에게만 보이므로 우리가 모른다**(§1 이 첫날 가드를 세운 것과 같은 이유).

- 저장은 §3 표대로 **zustand persist**(AsyncStorage). Idea Repository `lib/language.ts` 승계.
- 첫 실행에 **기기 언어로 한 번 정해지고**, 그 뒤로는 사용자 선택이 이긴다. 상태는 늘 `en|ko` 둘 중 하나다.
- 🔄 2026-09-18 화면은 언어 카드 목록에서 **셀렉트 하나**로 바뀌었다(사용자 지시 *"언어는 select 태그로 선택할 수 있게 처리해줘"* · 부품 `Select` · `UI_GUIDE.md` §2). 목록의 이름은 §2.2 대로 그 언어 자신의 표기다. 🟢 언어가 늘어도 설정 화면 길이가 안 는다.
- ⚠ **저장된 선택이 기기 언어와 다르면 부팅 시 한 프레임 깜빡인다**(i18n 초기값은 기기 언어이고
  복원은 비동기다). 형제도 같고, 이걸 없애려고 **부팅에 게이트를 세우지 않는다** —
  스플래시로 막다가 복원이 실패하면 흰 화면이 되는 쪽이 훨씬 나쁘다.

### 2.2 🔴 언어 이름은 locale 파일에 넣지 않는다

`English` · `한국어` 처럼 **그 언어 자신의 표기(autonym)** 를 쓴다. 번역하지 않는다 —
한국어 UI 에서 영어를 "영어"라고 적으면, 영어만 읽는 사용자가 자기 언어를 못 찾는다.

🔴 **그래서 `en.json` 에 `한국어` 를 넣으면 안 된다.** 넣는 순간 `check:i18n` ④(비한국어 파일에
한글 잔존)가 **정당하게 FAIL** 한다 — 가드가 틀린 게 아니라 키를 잘못 둔 것이다.
→ autonym 은 **코드 상수**(`features/settings/language.ts` 의 `LANGUAGE_NAMES`)로 둔다.

### 2.3 실측 (2026-09-09 · 에뮬 `reread`)

| 확인 | 결과 |
|---|---|
| 설정에서 `English` 선택 | 화면이 **즉시** 영어로 바뀐다(재시작 불필요) |

## 3. 🔴 세 개의 언어 축을 섞지 않는다

이 앱에는 **언어가 세 개** 있다. 하나로 묶으면 반드시 틀린다.

| 축 | 무엇 | 어디에 저장 |
|---|---|---|
| **UI 언어** | 앱 화면의 언어 | 설정(zustand persist) |
| **원문 언어** | 책 문장의 언어 | `knowledge.lang` (카드마다 다르다) |
| **AI 응답 언어** | 분석·회상 질문의 언어 | 설정 전역 하나. 기본값 **"앱 언어와 같음"** |

### 3.1 왜 분리하나

한국인 사용자가 영어 원서를 읽는다. UI는 `ko`, 원문은 `en`, 분석은 `ko`로 받고 싶다.
반대로 영어 학습이 목적이면 분석도 `en`으로 받고 싶을 수 있다.

- 🔴 **원문은 절대 번역해서 저장하지 않는다.** 저장된 것은 사용자가 본 그 문장이다.
  복습에서 공개하는 것도 원문 그대로다.
- AI 프롬프트는 **원문 언어와 응답 언어를 명시적으로 분리해 지시**한다(`AI_SYSTEM.md` §6).
- `ai_analyses.lang`에 어떤 언어로 썼는지 남긴다 — 설정을 바꿔도 옛 분석은 그 언어 그대로다.

## 5. 가드 — `npm run check:i18n`

✅ **Phase 0에서 만들었다**(`scripts/check-i18n.mjs`). **여섯 축**을 본다(①~④ Idea Repository 승계):

```
① 키 누락    en 에 있고 ko 에 없는 키
② 키 잉여    ko 에만 있는 키
③ 보간 일치  같은 키의 {{변수}} 집합이 언어 간 동일한가
④ 잔존 한글  en.json 등 비한국어 파일에 한글이 남아 있는가
⑤ 없는 키    화면이 부르는 t('...') 가 리소스에 실제로 있는가   (2026-09-09 신설)
⑥ 죽은 키    리소스에 있는데 화면이 아무도 안 부르는 키          (2026-09-09 신설)
```

🔴 **①②만으로는 반쪽이다.** 둘은 **언어끼리만** 대조하므로 en·ko 에서 **동시에** 벌어진 일은
전부 통과한다 — 같이 지우면 ⑤ 가, 같이 남기면 ⑥ 이 잡는다. 실제로 같은 날 둘 다 겪었다(§5.2).

**⑥ 의 예외** — 아직 화면이 없는 키는 `PLANNED` 목록에 **이유와 함께** 적어야 통과한다.
🔴 그 목록도 스스로 늙지 않는다: 적어 둔 키가 실제로 쓰이기 시작하거나 리소스에서 사라지면
가드가 *"목록에서 빼라"* 로 FAIL 한다.
⚠ 템플릿 리터럴(`` t(`books.status.${s}`) ``)은 정적으로 못 푸니 **접두사까지만** 딴다 —
`books.status.` 아래는 전부 쓰인 것으로 친다. ⑤·⑥ 은 완전 탐지가 아니라 **하한**이다.

🔴 **가드를 만들면 [`README.md`](./README.md) §3 검증 루틴에 명령을 추가하는 것까지가 완료다.**
안 넣으면 다음 전체 테스트에서 안 돈다.

⚠ 가드에 **변이를 주입해 이빨을 확인한다**(키 하나 지우기 · 보간 바꾸기 · 한글 넣기 —
셋 다 잡히는가). 통과만 확인하면 가드가 조용히 죽어 있어도 모른다.

### 5.1 🔴 이 가드는 형제에서 **19일간 죽어 있었다** (2026-09-08 공유)

우리가 Phase 0에서 베낄 원본(`idea_repository/scripts/check-i18n.mjs`)이 바로 그것이다.
파이썬 heredoc·sed 를 거쳐 파일을 쓸 때 **`\b` 가 제어문자 `0x08` 로 박혔다.**

```
의도:  /\bt\(\s*'([^']+)'/g       → t('key') 호출 수집
실제:  /<0x08>t\(\s*'([^']+)'/g   → 항상 0건
결과:  "리소스에 없는 키" 검사가 2026-08-20 부터 19일간 FAIL 불가 상태로 초록이었다
```

🔴 **에러 없이 아무것도 매칭하지 않고 통과한다.** 화면에도 안 보인다.
검사 **개수**로는 절대 안 잡힌다 — 개수는 실행량이지 검증량이 아니다.

**그래서 이 프로젝트의 규칙:**

- 🔴 **정규식·이스케이프가 든 파일은 heredoc/sed 로 쓰지 않는다. Write 도구로 쓴다.**
  굳이 스크립트로 조립해야 하면 `chr(92)` 로 백슬래시를 만든다.
  (이 세션도 2026-09-08에 같은 것을 밟았다 — `D:\emulators\reread` 의 `\r` 이 CR 로 박혔다)
- 🔴 **변이 주입에 "양성 대조"를 포함한다** — 잡히는지만 보지 말고
  **정규식이 실제로 무언가를 수집하는지**(0건이 아닌지)를 함께 본다. 위 사고는
  "변이가 안 잡힌다"가 아니라 "아무것도 안 본다"였고, 앞의 검사로는 안 걸린다.
- 스윕 명령은 [`README.md`](./README.md) §3.

### 5.2 🔴 대칭 사고 둘 — 같이 지워도, 같이 남겨도 안 걸렸다 (2026-09-09)

같은 날 같은 구멍에서 두 번 샜다. **둘 다 ①~④ 를 전부 통과했다.**

| 무엇 | 어떻게 났나 | 왜 안 걸렸나 | 닫은 축 |
|---|---|---|---|
| `knowledge.thoughts.*` 4키를 **양쪽에서 지웠다** | 화면은 그대로 `t()` 를 부르는데 리소스가 없어 **키 문자열이 그대로 화면에 나갈 뻔** | ①② 는 언어끼리만 본다 — 대칭이라 차이가 0 | **⑤** |
| 디자인 패스에서 화면을 걷어내며 `home.today.reviewCount` · `knowledge.tags.empty` 를 **양쪽에 남겼다** | 아무도 안 부르니 ⑤ 에도 안 걸린다. 화면은 멀쩡하고 **다음 번역가만 일이 는다**(15개 언어면 15배) | 죽은 키를 보는 축이 아예 없었다 | **⑥** |

★ 두 사고의 모양이 같다 — **"두 파일을 대칭으로 틀리면 대조 검사는 침묵한다."**
그래서 이제 리소스는 **소스와도** 대조한다(⑤·⑥). 변이 확인: 죽은 키 심기 → FAIL ·
`PLANNED` 키를 리소스에서 지우기 → *"예외 낡음"* FAIL · 동적 접두사 아래 키 → 통과(설계대로).
