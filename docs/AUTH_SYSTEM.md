## 1. 연령 게이트 — 조각 방식 그대로 (결정 #25)

### 1.1 결정

사용자 결정(2026-09-14): *"조각 방식과 동일하게 연령 확인 진행해"*. 미결정 G 를 닫는다.

같은 날 형제 여덟 앱을 조사했다. 게이트를 만든 앱은 넷(조각 · Delvewarden · 배구명가 · 농구명가)이고,
안 만든 앱은 넷(LinkMemo · Idea Repository · My Word · SnoreLess)이다. **조건이 가장 가까운 것이 조각**이다:
로그인 없이 시작하고, 구글 로그인은 문의·구독·백업·AI 에서만 쓰고, 기록의 정본이 기기에 있고, 수익은 구독이다.
로그인이 필수인 게임 셋의 "부팅 = 로그인 앞" 구조는 조각 문서가 스스로 *"그 앱들이 로그인 필수라서 그런 모양"* 이라고 갈라 뒀다.

### 1.2 🔴 부팅에 서지만 **벽이 아니다**

```
실행 → [연령 게이트] ─통과→ (Phase 7: 기기 세션 발급 · 로그인 가능) · 저장 · 복습 · 실천
                     ├미달→ (Phase 7: 기기 세션 없음 · 로그인 막힘)   · 저장 · 복습 · 실천
                     └닫음→ 아무것도 저장 안 함 · 다음 실행에 다시 묻는다
```

- 🔴 **닫든 미달이든 저장·복습·실천·사진 가져오기·백업은 그대로다.** 미달 판정이 막는 것은 **계정이 필요한 기능**뿐이다.
- 게이트는 결과를 **기다리지 않는다.** 모달이 떠 있는 동안에도 부팅의 나머지(알림 예약 맞추기 등)는 돈다.

#### 솔직하게 적는 것 — 지금은 부팅에 막을 식별자가 없다

조각이 게이트를 로그인 지점에서 부팅으로 옮긴 이유는 **부팅에 기기 UUID 를 발급**하게 됐기 때문이다
(*"우리가 처리자가 되는 첫 식별자가 어디서 생기나"* 가 위치를 가른다).
🔴 **Re:Read 는 지금 부팅에 우리 식별자를 만들지 않는다**(네트워크 호출 0건 · `check:privacy` ②).

그래도 부팅에 두는 이유는 셋이다.
1. 사용자 결정이 *"조각과 동일하게"* 다.
2. `CLAUDE.md` §4.1 이 이미 *"조각이 겪은 대로 부팅에 세운다(기기 식별자 발급 전에 판정)"* 로 적어 뒀다.
3. Phase 7 이 common_server 기기 등록·하트비트를 붙이는 날 **경계가 부팅이 된다.** 지금 세워 두면 그때 부팅 순서를 다시 짜지 않는다(`PLAN.md` Phase 11 ⚠).

⚠ **게이트가 못 막는 식별자가 하나 있다.** 업데이트 토큰 `EAS-Client-ID` 는 `expo-updates` 가 **네이티브에서, JS 보다 먼저** 만든다.
처리방침 §4 가 *"기기에서 생성한 무작위 식별자"* 로 이미 고지했고, 이름·계정과 연결되지 않는다.

**대가**: 첫 실행에 질문이 하나 는다(기둥 1). 줄이는 장치는 조각과 같다 — **1회성**(통과 기록이 남는다) · **벽이 아니다** · **닫아도 된다**.

### 1.3 판정 — 지역별 16 / 14 / 13, 판정 불가는 16

| 지역(기기 로케일의 지역 코드) | 기준 | 근거 |
|---|---|---|
| EEA + 영국 + 스위스(32개국) | **16** | GDPR §8. 회원국이 13~16 에서 정하므로 16 이면 어디서도 안전 |
| 한국 | **14** | 개인정보보호법 §22조의2 |
| 미국 | **13** | COPPA |
| 그 외 | **13** | 보수적 기본값 |
| **판정 불가** | **16** | 🔴 로케일 읽기는 실패할 수 있다. 실패가 가장 느슨한 기준으로 떨어지면 게이트가 무의미해진다 |

**판정식은 보수적으로**: `올해 − 출생연도 ≥ 기준 + 1`. 연도만 받으면 실나이가 최대 12개월 흔들려,
관대식은 기준 미달자를 들여보낸다(**위법**). 보수식의 대가는 자격자가 최대 11개월 늦게 들어오는 것이다.
🚫 **월·일을 더 묻지 않는다.** 수집을 늘리는 쪽이다.

⚠ 지역은 IP 가 아니라 **기기 로케일**로 읽는다. 🚫 앱 UI 언어로 읽지 않는다(영어 UI 를 쓰는 한국 거주자가 13 으로 떨어진다).

### 1.4 무엇을 저장하나 — 생년은 저장하지 않는다

| 키(AsyncStorage) | 값 |
|---|---|
| `reread-age-pass` | `{ passedAt, threshold, version }` |
| `reread-age-block` | `{ blockedAt, threshold, version }` |

- 🔴 `makeRecord(threshold, now)` · `makeBlockRecord(threshold, now)` 는 **생년을 인자로도 받지 않는다.** 실수로 같이 저장되는 경로를 타입에서 없앤다.
- 🔴 **서버로 아무것도 보내지 않는다.** → Play 데이터 보안 선언이 바뀌지 않는다.
- 조각은 SQLite `app_settings` 에 뒀다(앱 초기화의 사정권 안). 우리는 **AsyncStorage** 에 둔다.
  🟢 백업 **교체**(`BACKUP_SYSTEM.md` §4)는 DB 만 바꾸므로 연령 기록을 건드리지 않고, 백업 파일에도 들어가지 않는다.
  앱을 지우면 사라진다 = 새 설치 재확인(공용 §4).

### 1.6 화면 — `components/AgeGate.tsx`

- 🔴 **중립으로 묻는다.** `만 N세 이상입니다 ☑` 는 정답이 보여서 FTC 의 *neutral age screen* 이 아니다. 태어난 **연도 목록**을 고르게 하고, 최근 해가 위다.
- 왜 묻는지와 *"고른 연도는 저장하지 않는다"* 를 그 자리에 적는다.
- 미달 안내: **계속 쓸 수 있는 것**을 반드시 말한다(이 말이 없으면 미달자는 앱을 못 쓰는 줄 알고 지운다) · 문의 이메일 · 처리방침 링크 · 돌아가기.
- 🔴 같은 세션에서 **다시 입력할 수 없다.** *"다른 계정으로"* 같은 대안을 제시하지 않는다(공용 §5).
- 앱 전체를 덮는 **층**이라 라우트가 아니다. `app/_layout.tsx` 가 한 번 그린다.

| 조각과 다른 점 | 조각 | Re:Read | 왜 |

### 1.9 처리방침 §9 를 고쳤다

게이트가 서면 §9 의 *"저희가 가진 데이터로는 이용자의 나이를 알 수 있는 방법이 없습니다"* 가 **말 그대로는 여전히 참**이다(결과가 기기를 떠나지 않는다).

→ §9 에 **기기에서 하는 나이 확인** 문단을 넣고 버전을 1.0 → 1.1 로 올렸다. ⏸ 웹 게시본(`vivace-games.com/reread/privacy`) 갱신은 사용자 배포다.
