## 🔴 순서를 이렇게 잡은 이유

1. **핵심 루프(저장 → 복습)를 서버 없이 먼저 완성한다.** Phase 0~6까지 네트워크가 하나도 없다.
   로컬 정본(결정 #1)의 실질적 이득이 여기다 — 계정·결제·AI 없이 제품의 심장이 도는지 볼 수 있다.
2. **알림(Phase 4)을 일찍 시작한다.** 🔴 하루짜리 테스트로는 안 잡히는 종류의 버그다
   (Doze·강제종료·재부팅). 이후 Phase 개발 내내 실기기에서 며칠 돌게 두고 관찰한다.
3. **AI(Phase 8)를 뒤로 뺀다.** 로그인(Phase 7)이 선행돼야 하고, 무엇보다
   **AI 없이도 제품이 성립하는지**(결정 #9)를 Phase 3에서 먼저 확인해야 한다.
4. **구독(Phase 10)이 늦다.** 단 🔴 **스토어 상품 등록은 심사 전에 돼야 하므로**
   Phase 10을 더 미루면 출시가 밀린다.

🔴 **착수 전 대조에서 문서 모순 셋이 나왔다 — 코드보다 문서를 먼저 고쳤다**(`CLAUDE.md` §13 ②).
§1.1은 "모든 표가 `deleted_at`을 가진다"인데 §2의 여섯 표에 그 칸이 없었고, §3은 **바로 그 표들을

`practice_logs`)와 tombstone이 부딪히는 자리는 어느 문서에도 답이 없었다.
→ `DATABASE.md` §1.1에 **예외 넷**을 표로 못 박고, §1.4 **되살리기 규칙**을 신설한 뒤 코드를 썼다.

⚠ **에뮬레이터·실기기에서 이 DB 가 열린 적은 없다.** 잰 것은 `node:sqlite` 에 같은 스키마·같은 러너를

**Phase 0 의 ⏸ 렌더 확인과 같은 축**이고 아직 안 닫혔다.

**실제로 만든 것**

- 책 등록 · 목록 · 상세(파생 집계) · 상태 3종
- 지식 카드 목록 · 상세 · 내 생각(1:N) · 태그

- 🟢 **로컬 내보내기/가져오기(결정 #15)** — JSON 한 파일 + OS 공유 시트(`expo-sharing`).
  설계는 `idea_repository/docs/BACKUP_SYSTEM.md` 승계(병합/교체 · 형식 식별자 · 손상 파일 거부)

**완료 기준** — 🔨 **CRUD 는 2026-09-09 에뮬 실측으로 닫혔다. 내보내기/가져오기가 남았다.**

```
[x] 책 없이 원문만으로 저장 → 목록에 뜬다      에뮬 실측(AVD reread · Expo Go)
[x] 저장 흐름의 필수 입력이 content 하나뿐      책·페이지·생각·태그 비운 채 저장됨
[x] 책 삭제 후 지식이 남고 book_id 가 NULL      🔴 화면에서 확인 — 삭제 후 카드가 `책 없음` 으로 남았다
[x] 지식 삭제 후 고아 태그 정리                 ⚠ check:db 로만 확인(기기에서는 안 밟았다)

[ ] 🟢 내보내기 → 앱 삭제 → 재설치 → 가져오기 → 데이터 동일 (결정 #15)
[ ] 🔴 가져오기가 tombstone 을 존중한다 (지운 것이 되살아나지 않는다)
[ ] 내보내기 화면에 "이 파일에 모든 내용이 그대로 들어 있다" 고지
```

🔴 **이 Phase 에서 처음 확인된 것 — expo-sqlite 가 기기에서 실제로 열린다.**
Phase 1 은 `node:sqlite` 로만 쟀고 "네이티브 적재·파일 경로·권한은 다른 축"이라고 ⏸ 를 남겼다.
홈 화면의 `책 · 0 / 문장 · 0` 이 그 축이 닫혔다는 첫 증거였고(카운트 쿼리가 돌았다는 뜻),
그 뒤 저장·수정·삭제가 전부 재부팅 없이 반영됐다.

**실제로 만든 것**
```
app/index.tsx                     홈 — 저장이 1탭 거리(§1.2) · 최근 3건 · 파생 카운트
app/knowledge/new.tsx             빠른 저장 — 🔴 원문만 채우면 저장 버튼이 열린다
app/knowledge/index.tsx           문장 목록
app/knowledge/[id].tsx            상세 — 원문 수정 · 책 연결 · 태그 붙이기/떼기 · 생각 1:N · 삭제
app/books/{index,new,[id]}.tsx    책 목록 · 등록 · 상세(파생 집계 4종 · 🔴 삭제 경고에 문장 수)
features/{books,knowledge,tags}/  도메인 계층 — 화면은 SQL 을 모른다
components/{Button,Field,Card,Header}.tsx · hooks/useDbQuery.ts
```
⚠ **`useDbQuery` 는 포커스가 돌아올 때마다 다시 읽는다.** 안 그러면 다른 화면에서 지운 것이
목록에 남아 보인다 — `DATABASE.md` §1.1 의 "빈 화면이 아니라 틀린 화면"이 UI 층에서 재현되는 자리다.

### ★ 판정 게이트를 숫자로 고정했다 (2026-09-09) — 🔴 사용자 확인 필요

**"테스터 N명이 7일 중 5일 이상 오늘의 복습을 소진"** 이었다.

🔴 **그 제안은 우리 테스터 구성으로는 잴 수 없다.** `common/PLAY_CONSOLE_STATUS.md` §2-1 실측:
doply 테스터는 **비공개 테스트 요건을 채우려고 설치할 뿐 다시 열지 않는다**(조각의 설치 17이 전원 그렇다).
그 사람들에게서 "7일 중 5일"은 나올 수가 없다 — 기준을 그대로 두면 **영원히 미달**이거나,
더 나쁘게는 **아무도 안 재고 통과**시킨다.

→ **잴 수 있는 것으로 바꾼다:**

```

```
