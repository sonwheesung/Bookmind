## 🔴 순서를 이렇게 잡은 이유

1. **핵심 루프(저장 → 복습)를 서버 없이 먼저 완성한다.** Phase 0~6까지 네트워크가 하나도 없다.
   로컬 정본(결정 #1)의 실질적 이득이 여기다 — 계정·결제·AI 없이 제품의 심장이 도는지 볼 수 있다.
2. **알림(Phase 4)을 일찍 시작한다.** 🔴 하루짜리 테스트로는 안 잡히는 종류의 버그다
   (Doze·강제종료·재부팅). 이후 Phase 개발 내내 실기기에서 며칠 돌게 두고 관찰한다.
3. **AI(Phase 8)를 뒤로 뺀다.** 로그인(Phase 7)이 선행돼야 하고, 무엇보다
   **AI 없이도 제품이 성립하는지**(결정 #9)를 Phase 3에서 먼저 확인해야 한다.
4. **구독(Phase 10)이 늦다.** 단 🔴 **스토어 상품 등록은 심사 전에 돼야 하므로**
   Phase 10을 더 미루면 출시가 밀린다.

## Phase 12 — v1.1 백업 금고 🔴 출시 직후 최우선

**목표**: 결정 #1의 대가(기기 교체 시 전손)를 닫는다. **"2차 개발"이 아니다.**

- 조각 `server/`의 백업 금고를 복사 승계 — `vaults · vault_grants · generations · generation_parts · vault_blobs`
- 클라이언트 암호화 · 복구 코드(HKDF) · 🔴 `auth_hash` 를 `vault_id` 와 **다른 값**으로
- 리퍼(3년 무접근) · 구독 만료 유예 90일 스냅샷
- 🔴 고지 문구는 **"읽지 못합니다"** — AI의 "저장하지 않습니다"와 다르다. i18n 키 분리

**완료 기준**
```
[ ] 백업 → 앱 삭제 → 재설치 → 복원 → 데이터 동일
[ ] 🔴 복원이 지운 항목을 되살리지 않는다 (tombstone 검증)
[ ] 서버에서 평문을 얻을 수 없다 (직접 시도해 확인)
[ ] 세대 건너뛰기 거부(seq+1만 수용) · 재시도 멱등
[ ] 처리방침 개정 + 시행 고지 발행
```
