## 1. 저장 (`KNOWLEDGE_SYSTEM.md` §1)

| 상황 | 기대 동작 | |
|---|---|---|
| 원문만 넣고 저장 | 성립한다. 책·페이지·생각·태그 전부 비어도 된다(기둥 1) | ✅ |
| 공백만 있는 원문 | 저장 버튼이 **잠긴다.** 빈 카드가 생기면 안 된다 | ✅ |
| 공백만 있는 생각·태그 | 빈 행을 만들지 않는다 | ✅ |
| 같은 문장을 두 번 저장 | **허용한다.** 🚫 중복 검사를 넣지 않는다 — 흐름을 끊는 것이 더 나쁘다 | 🚫 |
| 한 챕터를 붙여넣기(2,000자) | 저장된다. 목록은 3줄로 줄이고 상세에서 전문을 본다 | ✅ |
| 🔧 **긴 원문을 넣는 동안 저장 버튼이 화면 밖으로 밀린다** | 입력칸에 상한을 두고 그 안에서 스크롤한다. **저장 동선이 막히면 기둥 1 위반**이다 | 🔧 2026-09-09 |
| 🔧 **저장 버튼을 빠르게 두 번 누른다** | 한 건만 저장된다. 화면을 떠나므로 두 번째 탭이 들어올 틈이 있다 | 🔧 2026-09-09 |

## 2. 지식 카드 상세

| 상황 | 기대 동작 | |
|---|---|---|
| 🔴🔧 **[수정]에서 원문을 지우고 [저장]** | 저장 버튼이 **잠긴다.** 고치기 전에는 예외가 나고 사용자에게는 **아무 일도 안 일어난 것처럼** 보였다 — 릴리스에서는 조용한 먹통이 된다 | 🔧 2026-09-09 |
| [수정] 후 [취소] | 원래 내용으로 돌아온다 | ✅ |
| 🔧 **긴 생각이 여러 건** | 최신 하나만 펼치고 나머지는 접는다(§3). 안 접으면 삭제 버튼까지 스와이프 세 번이 걸렸다 | 🔧 2026-09-09 |
| 🔧 **생각 [떼기]** | 확인을 묻는다. 되돌릴 수 없는데 문장·책 삭제에만 확인이 있었다 | 🔧 2026-09-09 |
| 책 연결을 나중에 붙이기 | 언제든 붙이고 뗄 수 있다(§1.1) | ✅ |

## 3. 태그 (`KNOWLEDGE_SYSTEM.md` §5 · `DATABASE.md` §1.4)

| 상황 | 기대 동작 | |
|---|---|---|
| 같은 태그를 두 번 붙이기 | 중복 행이 생기지 않는다 | ✅ |
| `Habit` 과 `habit` | **같은 태그**로 본다(대소문자 무시) | ✅ |
| 뗐다가 **같은 이름을 다시** 붙이기 | 되살아난다. 🔴 새 행을 만들면 UNIQUE 위반으로 죽는다(§1.4) | ✅ |
| `a,,b , c ` 처럼 지저분한 입력 | 정확히 3개로 갈리고 빈 태그가 안 생긴다 | ✅ |
| 🔧 **상세에서 `alpha,beta` 입력** | 저장 화면과 **같은 규칙**으로 나눈다. 화면마다 규칙이 다르면 사용자는 두 번 배워야 한다 | 🔧 2026-09-09 |
| 🔧 **이미 붙어 있는 태그를 다시 추가** | 아무 일도 안 일어나는 대신 **그렇다고 말해 준다.** 조용하면 "안 눌렸나"로 읽힌다 | 🔧 2026-09-09 |
| 🔧 **태그 이름이 아주 길다** | 이름만 줄어들고 **제거 표식(×)은 남는다.** 라벨에 붙여 쓰면 × 까지 잘려 "못 지우는 태그"가 된다 | 🔧 2026-09-09 |

## 4. 삭제 규칙 (`DATABASE.md` §3)

| 상황 | 기대 동작 | |
|---|---|---|
| 🔴 **책을 지운다** | 지식은 **남고** `book_id` 만 끊긴다. 확인 문구가 **남는 문장 수**를 정확히 말한다 | ✅ |
| 지식을 지운다 | 목록·홈 카운트에서 사라진다. 실천은 남고 복습 로그도 남는다 | ✅ |
| 지식을 지운 뒤 태그 | 그 지식만 쓰던 태그는 정리되고, **다른 지식이 쓰는 태그는 남는다** | ✅ |
| 지운 지식이 복습 큐에 | 나타나지 않는다. 두 겹으로 막고 가드가 매번 잰다 | ✅ (가드) |
